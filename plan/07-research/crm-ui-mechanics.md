# Research: CRM and B2B data-tool UI mechanics

- **Researched by:** research agent (+ four parallel sub-agents: Attio/Folk/Close, Linear/Notion/Airtable, Pipedrive/HubSpot/Salesforce, Twenty/Retool)
- **Date:** 2026-08-24
- **Confidence:** **High** where a vendor publishes source code or a real design system (Twenty's repo, Salesforce SLDS, Retool docs, Attio/Linear/Airtable/Pipedrive/Close help centres). **Medium** for HubSpot (Canvas publishes no component spec; help centre only) and Salesforce product behaviour (help.salesforce.com is a client-rendered SPA that returns a loading shell to fetchers, so several claims come from Trailhead or search snippets). **Low** for anything marked `UNVERIFIED` — mostly visual specifics (row heights, click-vs-double-click) that vendors simply do not document.

## Question

Our CRM has a working table, a two-column record page, a drag-and-drop kanban and a ⌘K palette. Before we invest further we need to know, in copyable detail, what the products reps actually like — Attio, Linear, Pipedrive, Folk, Twenty, Close, HubSpot, Salesforce Lightning, Airtable, Notion, Retool — concretely *do*: row heights, edit triggers, selection models, filter grammars, what sits in which column, what a stage header sums, what a command palette is allowed to do, and which CRM mechanics experienced users assume exist. Then: what are we missing?

---

## Findings

### 1. Record list / table views

**1.1 Row height: the real numbers.** Twenty hard-codes a single height — `export const RECORD_TABLE_ROW_HEIGHT = 32;` ([twentyhq/twenty RecordTableRowHeight.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-table/constants/RecordTableRowHeight.ts), read 2026-08-24) — **no density switch at all**. Retool's Table exposes five named options: **X-Small 20px, Small 32px, Medium 48px, Large 60px, Dynamic** (grows to content) ([Retool table customization](https://docs.retool.com/apps/guides/data/table/customization), read 2026-08-24). Airtable names four: **Short** (default and densest), **Medium**, **Tall**, **Extra Tall**, changed from a "row height switcher in the view bar"; taller rows exist specifically to show "multiple lines of text… multiple lines of linked records… larger images" ([Airtable grid view help](https://support.airtable.com/docs/airtable-grid-view), read 2026-08-24). Notion's table has **no** row-height preset — height is content-driven, and the only lever is a per-property **"Wrap text"** toggle reached by clicking the property name ([Notion – Tables](https://www.notion.com/help/tables), read 2026-08-24); Notion *Gallery* view does have Small/Medium/Large card size, default Medium. Vendor-neutral guidance names the same three steps in px: **Condensed 40 / Regular 48 / Relaxed 56** ([Pencil & Paper: enterprise data tables](https://www.pencilandpaper.io/articles/ux-pattern-analysis-enterprise-data-tables), read 2026-08-24). Attio's main table row height is `UNVERIFIED` — not documented.

**1.2 Twenty's other grid constants** (all from the same `record-table/constants/` directory, read 2026-08-24): `RECORD_TABLE_COLUMN_MIN_WIDTH = 104`, `RECORD_TABLE_COLUMN_CHECKBOX_WIDTH = 28`, `RECORD_TABLE_COLUMN_DRAG_AND_DROP_WIDTH = 12` (the drag-handle gutter), `RECORD_TABLE_COLUMN_ADD_COLUMN_BUTTON_WIDTH = 32` (trailing "+"), `RECORD_TABLE_LABEL_IDENTIFIER_COLUMN_WIDTH_ON_MOBILE = 38`. Note a **trailing "+ add column" button is a first-class part of the grid**, not a toolbar item.

**1.3 Sticky first column is a z-index architecture, not one CSS rule.** Twenty publishes its whole stacking model ([TableZIndex.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-table/constants/TableZIndex.ts), read 2026-08-24):
```ts
base: 1, hoverPortal: 4, headerRow: 10,
cell: { default: 3, sticky: 8, editMode: 30 },
headerColumns: { headerColumnsSticky: 14, headerColumnsNormal: 10 },
groupSection: { stickyCell: 9, normalCell: 8 },
columnGrip: 30, rowDropLine: 9,
footer: { default: 8, stickyColumn: 9 },
```
Read this as the spec: a sticky cell outranks a normal cell, an **editing** cell outranks everything (30), the resize grip shares that tier, and there is a **`rowDropLine`** (drag-reorder insertion line) and a **sticky footer cell** for the aggregate row. Twenty also tracks horizontal/vertical **scroll-shadow visibility via CSS variables** (`RecordTableHorizontalScrollShadowVisibilityCssVariableName`, same directory) — the shadow that tells you a frozen column is covering content. Generic guidance agrees the sticky leftmost column "is just as important as the fixed header is for the regular vertical scroll" ([Pencil & Paper](https://www.pencilandpaper.io/articles/ux-pattern-analysis-enterprise-data-tables), read 2026-08-24). Notion has an explicit **"Freeze up to column"** command on the property-name menu, with "Unfreeze columns" to reverse; the API exposes it as `frozen_column_index` ([Notion tables help](https://www.notion.com/help/tables) and [developers.notion.com](https://developers.notion.com/), read 2026-08-24). Retool: **no documented column pinning or freezing at all** — `UNVERIFIED`, and the absence across the columns page, customization page and sitemap search is reasonably strong negative evidence.

**1.4 First column = identity, and clicking it navigates instead of editing.** This is the single most copyable mechanic found. Twenty's `openTableCell` branches: if the cell is in the **label-identifier (first) column and is non-empty**, it calls `openRecordFromIndexView` — opening the record (side panel or full page per a resolved per-object "open record in" setting) — rather than entering edit mode; **any other column, or an empty first-column cell**, enters edit mode ([useOpenRecordTableCell.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-table/record-table-cell/hooks/useOpenRecordTableCell.ts), read 2026-08-24). So "click the name to open, click anything else to edit, click an *empty* name to name it" is deliberate. Airtable's primary field is structurally the record's identity column, used wherever the record is referenced (linked-record chips, search). Attio's first column is `UNVERIFIED` in first-party text, though its App SDK documents a `<Table.Cell.Avatar />` cell type with `name` + `src` (null → initials fallback) and a rule that an avatar/badge cell may contain *only* that type ([docs.attio.com SDK Table](https://docs.attio.com/sdk/components/table), read 2026-08-24). Folk's People table row shows "avatar, first/last name, company, job title, primary email, and group assignments on the right" ([Folk – Search & organize contacts](https://help.folk.app/en/articles/6819356-search-organize-contacts), read 2026-08-24).

**1.5 Two-state focus model: "soft focus" then edit mode.** Twenty keeps *two separate* pieces of state — `recordTableFocusPositionComponentState` (which cell is highlighted and arrow-navigable) and `recordTableCellEditModePositionComponentState` (which cell has an open input), plus `isRecordTableCellFocusActiveComponentState` gating focus hotkeys ([states/ directory](https://github.com/twentyhq/twenty/tree/main/packages/twenty-front/src/modules/object-record/record-table/states), read 2026-08-24). The literal term "soft focus" is `UNVERIFIED` as documented vocabulary, but the two-atom mechanism is confirmed in code. This matches the W3C grid pattern exactly: **Enter** "disables grid navigation and either places focus in an input field or on the first widget"; **F2** toggles edit mode and again restores grid navigation; alphanumeric keys enter the input directly; **Escape** "restores grid navigation. If content was being edited, it may also undo edits" ([W3C ARIA APG – Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/), read 2026-08-24).

**1.6 Keyboard navigation semantics differ on wrap.** Twenty's `moveUp`/`moveDown` clamp at the first/last row; **`moveRight` at the last column jumps to column 0 of the next row**, and `moveLeft` at column 0 jumps to the last column of the previous row — Excel-style wrap, no-op at the grid corners ([useRecordTableMoveFocusedCell.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-table/hooks/useRecordTableMoveFocusedCell.ts), read 2026-08-24). The ARIA pattern says the opposite for data grids — "if focus is on the right-most cell in the row, focus does not move" — plus Home/End = first/last cell in row, Ctrl+Home/Ctrl+End = first/last cell in grid, PageUp/PageDown = author-determined row count, and a **roving tabindex** so only one cell is in the page tab sequence ([W3C APG Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/), read 2026-08-24). Attio: "Arrow keys navigate cells; Enter saves"; `cmd/ctrl+C` / `cmd/ctrl+V` copy-paste "across compatible attribute types"; multi-cell selection by click-drag or Shift+click; Tab-to-next-cell and Esc-to-cancel are `UNVERIFIED` ([Attio – Create and manage table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views), read 2026-08-24). Folk publishes the fullest keyboard table of the three: **Enter** edits a cell or moves to the next cell in the column, **Esc** exits edit mode, **Tab** next cell in row, `Cmd/Ctrl+←→` row ends, `Cmd/Ctrl+↑↓` column ends, `Fn+↑↓` scrolls 10 cells, `Cmd/Ctrl+Fn+←→` table ends ([Folk shortcuts](https://help.folk.app/en/articles/5007580-what-are-folk-shortcuts), read 2026-08-24).

**1.7 Linear is not a grid, and that is a decision.** Linear has no cell-level editing. Editing happens by pressing a property shortcut while a row is *hovered or focused*: `S` status, `A` assignee, `I` assign-to-me, `P` priority (with `Shift+1..4` = Urgent/High/Medium/Low) ([Linear docs](https://linear.app/docs), read 2026-08-24). Navigation is `J`/`K` or arrows; **`X` toggles selection**; Shift+arrow or Shift+click extends a range; `Cmd/Ctrl+A` selects all; `Esc` clears; hovering "near the left edge of an issue" reveals its checkbox; **bulk actions appear in a bar at the bottom** and are also reachable by `Cmd/Ctrl+K` scoped to the selection or by right-clicking a selected row ([Linear – Select issues](https://linear.app/docs/select-issues), read 2026-08-24).

**1.8 Bulk selection and where the action bar goes.** Bottom-anchored is near-universal: Linear ("bulk actions will show up at the bottom"), Attio ("a dialogue box appears at the bottom of the view where you can click More ▾ to access additional options like Delete records" — add-to-list, run workflow, send emails, delete) ([Attio table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views), read 2026-08-24), Folk ("an action bar at the screen's center-bottom that displays the selected contact quantity and features an 'Enrich' button") ([Folk bulk actions](https://help.folk.app/en/articles/9465447-bulk-actions), read 2026-08-24). Checkbox-on-hover then actions-on-selection is the documented convention: "Once one or more rows are selected, only then is it relevant to display said actions" ([Pencil & Paper](https://www.pencilandpaper.io/articles/ux-pattern-analysis-enterprise-data-tables), read 2026-08-24). HubSpot's bulk edit is the most nuanced: for multi-select properties it offers **Append / Replace / Remove** modes, while single-select and text simply overwrite; several bulk actions cap at **100 records** (list membership, workflow/sequence enrolment) and bulk task creation only applies to records on the *current page* even after "select all pages" ([HubSpot – Bulk edit records](https://knowledge.hubspot.com/records/bulk-edit-records), read 2026-08-24). Salesforce's mass inline edit propagates one inline change to the whole selection but requires the list be filtered to a single record type and three admin permissions enabled ("Enable Inline Editing", "Enable Enhanced Lists", "Mass Edits from Lists"); the literal button copy is `UNVERIFIED` ([Trailhead – list views](https://trailhead.salesforce.com/content/learn/modules/lex_customization/lex_customization_list), read 2026-08-24).

**1.9 Spreadsheet paste and drag-fill.** Attio copy/paste "works between Attio views and external spreadsheet applications (values must be compatible with target attribute types)" ([Attio table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views), read 2026-08-24). Airtable documents the fill handle precisely: select a cell, "hover your cursor over the small box in the right-hand corner… and drag the handle"; horizontal or vertical, adjacent cells only; **"dragging the '1, 2' values of two cells will extend the numeric sequence to '1, 2, 3, 4…'"** but only if the field is typed as number or date ([Airtable fill handle](https://support.airtable.com/docs/quickly-filling-cells-using-fill-handle), read 2026-08-24). Folk documents dragging "the cell (like in Excel)" to apply a value down a column ([Folk bulk actions](https://help.folk.app/en/articles/9465447-bulk-actions), read 2026-08-24). Attio drag-fill is `UNVERIFIED`.

**1.10 Filter grammar — four distinct philosophies.**
- **Nested groups with AND/OR.** Attio: click `⋮` on a condition → "Convert to advanced condition" → `⋮` again → "Convert to group", then toggle And/Or. Attio's own guidance is worth quoting: *"Use Or when including records. A record appears in the view if it matches any one of the conditions… use And when excluding records. A record only appears if it meets every condition at the same time."* ([Attio – Filter and sort views](https://attio.com/help/reference/managing-your-data/views/filter-and-sort-views), read 2026-08-24). Linear opens filters with `F`, supports "grouping conditions and combining them with AND/OR logic (including nested filter groups)" via an "Advanced filter" builder, and **reflects applied filters in the browser URL** ([Linear – Filters](https://linear.app/docs/filters), read 2026-08-24). Notion nests filter groups **up to three layers deep** ([Notion – views, filters, sorts & groups](https://www.notion.com/help/views-filters-and-sorts), read 2026-08-24). Airtable nests to a hard **third level** ("the option to add a group will be grayed out"), caps at **49 conditions per view**, and warns that shared-view *URL* filters "cannot mix AND and OR logic or group conditions" ([Airtable – filtering with conditions](https://support.airtable.com/docs/filtering-records-using-conditions), read 2026-08-24).
- **Two named buckets.** Pipedrive uses an **ALL** group (AND) and an **ANY** group (OR), with the canonical teaching example that Won *and* Lost must go in ANY because a deal cannot be both; max **16 conditions per filter**, **5,000 filters per user**, and each filter is marked **Shared** or **Private** ([Pipedrive – Advanced filtering](https://support.pipedrive.com/en/article/filtering), read 2026-08-24). HubSpot: "Add filter" appends to the current AND group; "Add filter group" starts a new OR group; a record matching *any* group's full AND-set is included; column-header 3-dot → "Filter by this column" is in beta ([HubSpot – View and filter records](https://knowledge.hubspot.com/records/view-and-filter-records-in-the-updated-index-page), read 2026-08-24).
- **Single global toggle.** Folk offers only one AND/OR choice across all filters in a view ([Folk – Create views](https://help.folk.app/en/articles/4998224-create-views), read 2026-08-24).
- **A query language plus natural language.** Close builds filters either "directly into the top search bar or use the Narrow Your Results sidebar to add search syntax to the top search bar", with match operators `All of`, `Any of`, `Not all of`, `None of` plus an `is not` disqualifier; the API-level structure exposes `"and"`, `"or"`, `"field_condition"` (regular vs custom field), condition types `"text"` (`full_words`/`phrase`), `"number_range"`, `"term"`, `"exists"`, `"boolean"`, and **`"has_related"` for relationship traversal** ([Close – Search and Smart Views](https://help.close.com/docs/search-and-smart-views) and [developer.close.com advanced filtering](https://developer.close.com/resources/advanced-filtering/), read 2026-08-24). On top sits AI Search, with documented examples: *"All leads based on the West Coast who haven't been called this week"*, *"Which leads were created more than 60 days ago, that have never been contacted?"*
- **Twenty's operand vocabulary** is a good checklist for our own filter engine: `IS, IS_NOT, IS_NOT_NULL, IS_EMPTY, IS_NOT_EMPTY, CONTAINS, DOES_NOT_CONTAIN, LESS_THAN_OR_EQUAL, GREATER_THAN_OR_EQUAL, IS_BEFORE, IS_AFTER, IS_RELATIVE, IS_IN_PAST, IS_IN_FUTURE, IS_TODAY, VECTOR_SEARCH` ([ViewFilterOperand.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-shared/src/types/ViewFilterOperand.ts), read 2026-08-24). Note `IS_RELATIVE` / `IS_IN_PAST` / `IS_TODAY` — relative dates are field-level operands, not something the caller computes.

**1.11 The dynamic filter value nobody builds first: "current user".** Attio shipped it as a headline feature: *"Filter any user-type attribute by Current user, so the view always reflects whoever is looking at it"* — one saved view serves the whole workspace, "Pipelines show each rep their own deals, and reports are personalized to each viewer" ([Attio changelog – Filter by current user](https://attio.com/changelog/2026/filter-by-current-user), 29 Apr 2026, read 2026-08-24).

**1.12 Saved views: who owns them.** Attio views are **shared by default with an explicit fork**: "Click Save for everyone if you want the new filters to be applied to the view going forward for all team members, or select the arrow next to Save for everyone and select Save as new view" ([Attio – Filter and sort views](https://attio.com/help/reference/managing-your-data/views/filter-and-sort-views), read 2026-08-24); favouriting is private ("Favorites are only visible to you"), views are drag-reorderable and the top one is the landing page ([Attio – Manage lists](https://attio.com/help/reference/managing-your-data/lists/manage-lists), read 2026-08-24). Airtable makes the mode explicit at creation time: **Collaborative** (default; anyone can change its config), **Personal** ("Only the owner… can customize that view's filters, grouping, field visibility, field order, sorts, row heights, and record coloring"), **Locked** ("prevent all collaborators from changing a view's configuration… until it's unlocked by someone with Creator or Owner permissions") ([Airtable – getting started with views](https://support.airtable.com/docs/getting-started-with-airtable-views), read 2026-08-24). Close's Smart Views have three sharing tiers — **Private / Organization-wide / Specific team members** — and can reference *other* Smart Views via an `In Smart View` filter to merge dialling lists, or invert to `not all of` to exclude them ([Close – Search and Smart Views](https://help.close.com/docs/search-and-smart-views) and [Smart View tips](https://help.close.com/docs/smart-view-tips-and-suggestions), read 2026-08-24). Linear saves with `Option/Alt+V`, scopes views to Workspace or Team/Project/Initiative, and warns that "Sharing a link does not automatically give anyone access to a view, it must be shared first" ([Linear – Custom views](https://linear.app/docs/custom-views), read 2026-08-24). Salesforce lets each user **pin** a list view as that object's default ([Trailhead](https://trailhead.salesforce.com/content/learn/modules/lex_customization/lex_customization_list), read 2026-08-24).

**1.13 Views are persisted metadata, not client state.** Twenty's `ViewEntity` is the best available checklist of everything a view has to store: `id, name, objectMetadataId, type, key, icon, position, isCompact, isCustom, openRecordIn, kanbanAggregateOperation, kanbanAggregateOperationFieldMetadataId, calendarLayout, calendarFieldMetadataId, calendarEndFieldMetadataId, mainGroupByFieldMetadataId, shouldHideEmptyGroups, kanbanColumnWidth, anyFieldFilterValue, visibility, isSystemSideEffect, createdByUserWorkspaceId`, with one-to-many relations to `viewFields, viewFieldGroups, viewFilters, viewSorts, viewGroups, viewFilterGroups` — and a **database CHECK constraint** (`CHK_VIEW_CALENDAR_INTEGRITY`) forcing calendar views to carry their layout and date field ([view.entity.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-server/src/engine/metadata-modules/view/entities/view.entity.ts), read 2026-08-24). Its `ViewType` enum: `TABLE, KANBAN, CALENDAR, LIST, FIELDS_WIDGET, TABLE_WIDGET, KANBAN_WIDGET, LIST_WIDGET, CALENDAR_WIDGET` ([ViewType.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-shared/src/types/ViewType.ts), read 2026-08-24).

**1.14 Sorting indication and multi-level sort.** Attio: a "Sort" button, attribute + Ascending/Descending shown as ↑/↓, and multi-level sorts with drag-reorderable `⁚⁚⁚` handles — "records are sorted by the first attribute. If two or more records share the same value… the second sort is applied" ([Attio](https://attio.com/help/reference/managing-your-data/views/filter-and-sort-views), read 2026-08-24). Notion stacks sorts the same way with `⋮⋮` drag handles for priority. SLDS specifies the accessible version: an icon whose direction flips per state **plus an `aria-live="polite"` region announcing the new sort order**, with the sort icon's `margin-left` at `$spacing-xx-small` = 4px ([SLDS data-tables source](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/data-tables/docs.mdx), read 2026-08-24). Folk has a genuinely useful quirk: "when sorting by a select or multi-select field, Folk will apply the same order from the dropdown" — configured option order, not alphabetical ([Folk – Create views](https://help.folk.app/en/articles/4998224-create-views), read 2026-08-24).

**1.15 Per-column aggregate footers are table stakes.** Twenty's `AggregateOperations` enum: `MIN, MAX, AVG, SUM, COUNT, COUNT_EMPTY, COUNT_NOT_EMPTY, COUNT_UNIQUE_VALUES, PERCENTAGE_EMPTY, PERCENTAGE_NOT_EMPTY, COUNT_TRUE, COUNT_FALSE`, with a separate `DateAggregateOperations` = `EARLIEST, LATEST` and a `FieldTypesAvailableForNonStandardAggregateOperation` gate so options depend on field type ([constants directory](https://github.com/twentyhq/twenty/tree/main/packages/twenty-front/src/modules/object-record/record-table/constants), read 2026-08-24). Attio: "+ Add calculation" at the bottom of a column, numeric aggregations plus empty/filled tallies for non-numeric ([Attio table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views), read 2026-08-24). Airtable's summary bar is the richest documented set: non-numeric → Empty/Filled/%Empty/%Filled; checkbox → Unchecked/Checked/%; numeric → Sum, Average, Histogram, Min, Max, Range, Median, Standard Deviation; date → Earliest/Latest/Date Range (days)/Date Range (months); attachments → total file size; all types → Unique/%Unique — **and grouped records get a per-group summary as well as the overall total, while selecting a range of rows scopes the summary to the selection** ([Airtable summary bar](https://support.airtable.com/), read 2026-08-24). Retool's summary row offers Min, Max, Average, Sum, Count Distinct ([Retool table customization](https://docs.retool.com/apps/guides/data/table/customization), read 2026-08-24). Close added this recently: "New in Smart Views: Instantly see the sum, average, and more for column data" (changelog title, 6 Mar 2026; the detail page 404'd, so mechanics are `UNVERIFIED`) ([close.com/changelog](https://close.com/changelog), read 2026-08-24).

**1.16 Column management verbs.** Attio: drag headers to reorder or use "⭠ Move left" / "Move right ⭢"; "Hide attribute"; resize by dragging the edge of name cells; per-column **"Formatting"** for date/timestamp/currency (relative dates, decimal toggles, grouping); and **"Edit column label"**, which creates a *view-specific* label leaving the attribute name untouched, reversible with "Clear label" ([Attio table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views), read 2026-08-24). Salesforce uses a Visible/Hidden two-pane "Select Fields to Display" per list view ([Trailhead](https://trailhead.salesforce.com/content/learn/modules/lex_customization/lex_customization_list), read 2026-08-24). SLDS documents resize handles at `$spacing-large` = **24px** wide, narrowing to `$spacing-small` = **12px** on the last column, offset `-12px` right; header action buttons are **32px** tall; outer cell buffers are **24px**; a clamped multi-line cell maxes at **52px** with the fade gradient starting at **36px** ([SLDS data-tables `_index.scss`](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/data-tables/base/_index.scss), read 2026-08-24). The SLDS spacing scale itself: `xxx-small 2px, xx-small 4px, x-small 8px, small 12px, medium 16px, large 24px, x-large 32px, xx-large 48px` ([spacing.yml](https://raw.githubusercontent.com/salesforce-ux/design-system/master/design-tokens/aliases/spacing.yml), read 2026-08-24).

**1.17 Grouping with sticky group headers.** Linear groups by status, assignee, project, priority, cycle, label, parent issue, team, customer, release or SLA status, and "The grouping header will remain sticky as you scroll down"; a "No grouping" option exists specifically because **manual ordering requires No grouping + Ordering: Manual** ([Linear – Display options](https://linear.app/docs/display-options), read 2026-08-24). Twenty has a `record-table-section` module and `groupSection` z-index tiers (see 1.3), i.e. grouped table rows with their own sticky cells.

**1.18 Server-side pagination breaks filters.** Retool documents three server-side modes — limit/offset (`pagination.pageSize` + `pagination.offset`), cursor (next-cursor + has-next-page), and GraphQL Relay (`first`/`last`/`after`/`before`) — with `overflowType` either `"scroll"` or `"pagination"`, **and the blunt caveat "Filters do not function if server-side pagination is enabled"** ([Retool pagination](https://docs.retool.com/apps/guides/data/table/pagination), read 2026-08-24). Its search has explicit modes: `searchMode` = `fuzzy | caseInsensitive | caseSensitive | noFilteringOrSorting`.

**1.19 Retool's edit/commit model is worth copying wholesale.** Edits accumulate in **`changesetArray`** ("a list of rows, by index, with edited values and primary key") and `changesetObject`, with new rows in `newRows`; nothing saves until a query referencing them runs, and Retool auto-adds a **Save** action add-on to wire it; `table.clearChangeset()` resets all three. The legacy table's equivalents were named `recordUpdates` / `changeSet` ([Retool table reference](https://docs.retool.com/apps/reference/components/table) and [legacy comparison](https://docs.retool.com/changelog/table-legacy-comparison), read 2026-08-24). Columns are made editable individually ("click next to the column, then select **Make editable**"), and numeric editable columns take inline **Min**/**Max** constraints ([Retool columns](https://docs.retool.com/apps/guides/data/table/columns), read 2026-08-24). Retool also supports **dynamic per-row column settings** — format, label, visibility and editability driven by expressions such as `{{ item === 'discontinued' ? 'boolean' : 'string' }}`.

**1.20 Cell-level edit history.** Attio: right-click a cell → **"View edit history"**, Pro/Enterprise only ([Attio table views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-table-views) and [Attio community changelog](https://www.attio.community/c/changelog/view-attribute-edit-history), read 2026-08-24). Salesforce tracks up to **20 fields per object** (60 with the paid Field Audit Trail; Tasks/Events capped at 6), retained ~**18 months in UI / 24 via API** without the add-on ([search-aggregated help.salesforce.com "Field History Tracking Overview"](https://help.salesforce.com/), read 2026-08-24 — help.salesforce.com renders client-side, so this is snippet-sourced).

### 2. Record detail pages

**2.1 Attio moved its detail panel to the *left* in May 2026.** Verbatim: *"Your most-used screen, rebuilt for speed. Headline and actions are now top-left. Record name, key info, and primary actions in one place, so you can act without hunting. The detail panel is now on the left."* Also in that release: a **drag divider** to reallocate space between lists and activity; a **compact/standard toggle** on embedded list cards — "compact (more lists visible) and standard (edit in place)"; **"Search all attributes. Open the full attribute list and search by name to jump straight to what you need."**; automation events **collapsed by default** "to highlight important events and reduce noise"; and a **comment sidebar** openable from the header without leaving the record ([Attio changelog – Record page redesign](https://attio.com/changelog/2026/record-page-redesign), 28 May 2026, read 2026-08-24). Effectively two columns: left sidebar of sections, main area of tabs and widgets ([Attio – Create and view records](https://attio.com/help/reference/managing-your-data/records/create-and-view-records), read 2026-08-24).

**2.2 Attio caps the highlights panel at six.** "At the top of the Overview tab, you can display up to six attributes as highlight widgets by clicking + Add widget" ([Attio – Create and view records](https://attio.com/help/reference/managing-your-data/records/create-and-view-records), read 2026-08-24). Configurable tabs: **Overview** ("A summary of recent activity, including emails, tasks, meetings, notes, and files in one place"), **Activity**, **Emails** (multiple differently-filtered Emails tabs can coexist per object), **Files**, **Notes**, **Tasks**, **Calls**. Tabs are addable and drag-reorderable (or "⋮ → Move left/right") and configuration is restricted to Full-access members ([Attio – Configure record pages](https://attio.com/help/reference/managing-your-data/records/configure-record-pages), read 2026-08-24). Header actions: Compose email, Add to list, New note, Run workflow, New task, Enrol in sequence (people only) — themselves drag-reorderable.

**2.3 Salesforce's highlights panel is driven by a named artefact: the Compact Layout.** "The record highlights section in Lightning Experience uses the **first seven fields** on the compact layout", while "**up to ten fields**… populate the record highlights section… in the Salesforce mobile app"; the first field renders bold. Compact layouts can be assigned **per Record Type**, so different processes on the same object show different highlights, and the same layout also drives the hover/lookup card on record links and the expanded row of an Activity Timeline item ([Trailhead – Compact Layouts](https://trailhead.salesforce.com/content/learn/modules/lex_customization/lex_customization_compact_layouts) plus snippet-sourced help.salesforce.com "Compact Layout Limitations and Considerations", read 2026-08-24). SLDS's record-home page header shows up to **4** compact-layout fields horizontally, or **7** in a vertical variant that drops heading truncation for a denser field stack; emails/URLs auto-linkify and addresses render on two lines ([SLDS Page Header, archive mirror via search snippet], read 2026-08-24 — the `archive-*.lightningdesignsystem.com` hosts no longer resolve, so this is `UNVERIFIED` at verbatim level).

**2.4 Twenty replaced the fixed detail page with a widget/grid layout system.** `PageLayoutType` = `RECORD_INDEX | RECORD_PAGE | DASHBOARD | STANDALONE_PAGE`; `PageLayoutTabLayoutMode` = `GRID | VERTICAL_LIST | CANVAS (deprecated)`; and the `WidgetType` enum enumerates what can go in a tab: `VIEW, IFRAME, FIELD, FIELDS, GRAPH, STANDALONE_RICH_TEXT, TIMELINE, TASKS, NOTES, FILES, EMAILS, CALENDAR, FIELD_RICH_TEXT, WORKFLOW, WORKFLOW_VERSION, WORKFLOW_RUN, FRONT_COMPONENT, RECORD_TABLE, EMAIL_THREAD, CALL_RECORDING_SUMMARY, CALL_RECORDING_TRANSCRIPT, MESSAGE_CAMPAIGN_BODY, MESSAGE_CAMPAIGN_DETAILS` ([widget-type.enum.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-server/src/engine/metadata-modules/page-layout-widget/enums/widget-type.enum.ts), read 2026-08-24). Note that **Timeline, Tasks, Notes, Files, Emails, Calendar and an embedded related-record `RECORD_TABLE` are all just widget types** — not hard-coded page sections. Its `SummaryCard` renders avatar, `createdAt`, and the **label-identifier field as an editable `RecordTitleCell`** — the record's own title reuses the exact same field-cell component as the table ([SummaryCard.tsx](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-show/components/SummaryCard.tsx), read 2026-08-24). Side panel width is a theme constant: `sidePanelWidth: '500px'` ([ThemeCommon.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-ui/src/theme/constants/ThemeCommon.ts), read 2026-08-24).

**2.5 Peek / preview panels: open a record without leaving the list.** Linear's is the reference implementation. Verbatim: *"Peek is one of the semi-secrets of the Linear UI. It lets you view details of focused issues at a glance from any list or board view, similar to Quicklook in macOS."* `Space` toggles it, **holding** `Space` previews temporarily and closes on release, `↑`/`↓` move through adjacent records updating the preview live, `Esc` closes; it shows "description, assignee, status, priority, cycle, labels, estimate, creation date, and updated date"; and **it also works inside the command menu** — "peek automatically previews supported items as you move between them" ([Linear – Peek](https://linear.app/docs/peek), read 2026-08-24). Airtable uses the same key: "Click any cell in the row (record) that you want to expand and press **Space**", with `Shift+Space` expanding a single cell ([Airtable grid view](https://support.airtable.com/docs/airtable-grid-view), read 2026-08-24). HubSpot's is a right-side panel: in table view "hover over a record and click **Preview**", in board view click the card, from a record page hover an associated record → ellipsis → Preview. It shows "the record's properties, activities, and associations"; "Click a header to collapse or expand a section"; properties autosave on edit; activities can be added from icons at the top; associations via "Add"; a **"View record"** button upper-right goes to the full page. There are **no next/previous arrows** ([HubSpot – Preview a record](https://knowledge.hubspot.com/records/preview-a-record), read 2026-08-24). Folk calls it **"Side Peek"** — a right-hand panel while you keep browsing the list on the left, shipped Jan 2024, motivated by "providing more context makes the person feel more valued", and including a direct "Enrich" button ([Folk changelog – Side peek](https://www.folk.app/changelog/side-peek), read 2026-08-24). Notion makes it a per-database setting: `•••` → Layout → **"Open pages as"** → **Side peek** ("splits your screen in two"), **Center peek** ("a box that only uses the center, much like a popup"), or **Full page** ([Notion help, read 2026-08-24](https://www.notion.com/help/)). Twenty resolves it per object via `useResolveOpenRecordIn` / `OpenRecordIn.SIDE_PANEL`.

**2.6 Notion's property layout builder is the most explicit "what's pinned vs scrolled" model.** Three element types: **Pinned properties** ("always displayed immediately under the page title, horizontally" — sources disagree on the cap, one says up to 4, another up to 15, so the number is `UNVERIFIED`), **Property groups** (vertical stacks), and **Sections** which "work like toggles allowing you to expand/collapse them". Crucially, **property search still works "across collapsed sections and hidden properties"** — hiding never makes a field unfindable. Also configurable: property icons on/off, full-width page, and **Comment display: Default vs Minimal** ([Notion – Customize database layouts](https://www.notion.com/help/layouts), read 2026-08-24).

**2.7 Pipedrive's sidebar is per-user and section-based.** "…" → **Manage sidebar sections** gives drag-and-drop reordering (`=` handle) and per-section show/hide; each section expands/collapses via a chevron; a **"Show only filled fields"** toggle hides empty fields; a pencil on a section header opens **bulk edit for every field in that section at once**; "+ Custom field" adds fields inline. All of it is **per-user and never deletes data** ([Pipedrive – Detail view sidebar](https://support.pipedrive.com/en/article/detail-view-sidebar), read 2026-08-24).

**2.8 Inline edit triggers, product by product.** Pipedrive: click the value *or* the **pencil icon that appears on hover**; most fields **auto-save on blur with no Save button — except Deal Value, which requires an explicit Save click** ([Pipedrive – Updating items in the detail view](https://support.pipedrive.com/en/article/updating-items-in-the-detail-view), read 2026-08-24). Salesforce: click a field's hover pencil to turn it into an input in place; Dynamic Forms lets admins place individual fields anywhere, each independently editable (`UNVERIFIED` — not re-verified against a primary doc). HubSpot: click a property value in the sidebar, autosave. Attio's main attribute panel is directly editable inline; single-click vs double-click is `UNVERIFIED`. Generic guidance: "When a cell is made to look clickable with a text cursor on hover, it hints to the content being editable" ([Pencil & Paper](https://www.pencilandpaper.io/articles/ux-pattern-analysis-enterprise-data-tables), read 2026-08-24).

**2.9 Where activity sits, and how it is de-noised.** Attio's June 2026 timeline redesign: it "now includes all task events: overdue, upcoming, and completed, so the work tied to a record lives right next to its history", and — the detail worth stealing — "filter the timeline by event type… **and your selection is remembered per object**" ([Attio changelog – New activity timeline](https://attio.com/changelog/2026/new-activity-timeline), 29 Jun 2026, read 2026-08-24). Salesforce puts a **tabbed activity composer** above the timeline, with Email / Log a Call / New Task buttons whose presence and order admins control via the page layout's Actions section; the underlying primitive is the SLDS **Docked Composer** with five states (Open/Focused, Closed, Closed/Focused, Popped Out, Overflow Menu with numeric badge) and a call sub-variant with states queued/ringing/connected/cancelled/busy/failed/no-answer/finished/incoming/logged ([SLDS docked-composer](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/docked-composer/docs.mdx), read 2026-08-24). SLDS timeline items inherit width from their container and expand/collapse via a trigger wired with `aria-controls`/`aria-expanded` against the panel's `aria-hidden` ([SLDS activity-timeline](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/activity-timeline/docs.mdx), read 2026-08-24). Airtable puts comments **bottom-right of the expanded record**, `@mention` in the same place, auto-subscribing mentioned collaborators to the thread, and logs every comment into the record's activity feed and revision history ([Airtable help, read 2026-08-24](https://support.airtable.com/)). Close's activity feed is the right/main column with **pinned activities — max 5 — at the top**, keyword+date filtering that expands matching activities and highlights the phrase, and per-activity permalinks (`#activityId=…`) that "work exclusively for authenticated users within the same organization" ([Close – Leads feature guide](https://help.close.com/feature-guide/leads), read 2026-08-24).

**2.10 Close's three-panel lead page.** Left sidebar: open tasks, Opportunities (deal amounts + tags), contact list with action icons, custom fields. Centre: lead info + a communication composer (call/email/SMS/note). Right/main: chronological activity history. On mobile "the Lead details and Activity Feed are shown in separate tabs" — implying desktop deliberately keeps them side by side ([Close – Leads feature guide](https://help.close.com/feature-guide/leads), read 2026-08-24). The 2025 redesign claims it "loads 40% faster" and adds "in-line editing, split scrolling, and grouped SMS functionality" ([Close 2025 features](https://close.com/blog/close-features-sell-smarter-2025), read 2026-08-24).

**2.11 Related records: chips, embedded tables, and the toolbar that matters.** Attio's relationship tabs list connected records with a toolbar of **"Add to list", "Enroll in sequence", "Run workflow", "Send email", "Unassociate", "Delete"**, and a non-removable **"Lists"** sidebar section showing which lists include this record *plus its list-specific attribute values* ([Attio – Create and view records](https://attio.com/help/reference/managing-your-data/records/create-and-view-records), read 2026-08-24). Airtable: "Click the + icon inside a linked record cell to open the linked record picker" and "Click any linked record in the field to open its expanded record… without leaving the current table"; links are bidirectional — "adding or changing links in either field automatically updates the corresponding records" ([Airtable – linking records](https://support.airtable.com/articles/3370222027-linking-records-in-airtable), read 2026-08-24). Notion relations: click the cell to get a search/pick menu, hover an existing item for a "–" remove control; rollups display a single computed value, and "Rollups can only be sorted when they output a numeric value" ([Notion – relations & rollups](https://www.notion.com/help/relations-and-rollups), read 2026-08-24). Twenty embeds a whole `RECORD_TABLE` widget for related records, and shipped "relation layouts as tables/kanban/calendar" in mid-2026.

**2.12 Salesforce Path (stage guidance on the record).** Stages render as a horizontal nav with state classes `.slds-is-incomplete`, `.slds-is-complete` (checkmark), `.slds-is-current`/`.slds-is-active`, `.slds-is-won`, `.slds-is-lost`; a collapsible guidance panel holds per-stage coaching text and "key fields" editable inline; buttons exist for "mark complete" and "mark current"; and below 1280px container width it becomes a horizontally scrollable strip with scroll controls ([SLDS Path, spring-20 mirror](https://spring-20.lightningdesignsystem.com/components/path/), read 2026-08-24).

**2.13 SLDS docked panel widths, for reference:** small **240px**, medium **320px**, large **400px**, x-large **640px**, full **100%**; docked panels stay in flow and reflow the main content; on open, focus is trapped to the first focusable element and returned to the trigger on close ([SLDS panels](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/panels/docs.mdx), read 2026-08-24).

### 3. Pipeline / kanban boards

**3.1 A pipeline is a view, not a module.** Attio has no separate pipeline feature — a pipeline "is just a list switched into kanban view" ([CRM.org Attio review](https://crm.org/news/attio-review), read 2026-08-24). Columns come from a **status-type attribute** ("select a status attribute or create one"), re-groupable via **"Grouped by"** in View settings ([Attio – Create and manage kanban views](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views), read 2026-08-24). Airtable's Kanban stacks by a "single select, user, or linked record field" and is explicitly single-dimension: "records can only be grouped by one field at a time" ([Airtable kanban](https://support.airtable.com/articles/9686375912-getting-started-with-airtable-kanban-views), read 2026-08-24).

**3.2 Card content is configured, not hard-coded.** Attio: "+ Add attribute to view", drag to reorder, a **"Show attribute label"** toggle, a **"Hide empty attributes"** toggle, per-attribute `⋮` formatting — and "Attribute values can be viewed and edited **directly on kanban cards**" ([Attio kanban](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views), read 2026-08-24). Airtable has a **"Customize cards"** menu with per-field toggles plus "Hide all"/"Show all" and a **"Wrap long cell values"** toggle ([Airtable kanban](https://support.airtable.com/articles/9686375912-getting-started-with-airtable-kanban-views), read 2026-08-24). Notion's **Card preview** can be "Page content" ("If you have images on your page, the card will display whichever image comes first") or any Files & media property, with a **Fit image** toggle (on = whole image fits; off = cropped to fill) and a hover **"Reposition"** control to drag the image within the frame; card properties are toggled under **Property visibility** ([Notion boards help, read 2026-08-24](https://www.notion.com/help/)). Linear deliberately does **not** let you compose cards separately — board and list share the same Display Properties, and "Descriptions are not shown on cards. If an issue has many properties, not all properties may have space to be displayed on the card" ([Linear – Board layout](https://linear.app/docs/board-layout), read 2026-08-24). Pipedrive's deal card defaults to **title, contact, value, label, and owner**, customisable via deal-card customisation ([Pipedrive – Pipeline view](https://support.pipedrive.com/en/article/pipeline-view), read 2026-08-24). Folk: "choose which fields to display on each contact cards, and order them" ([Folk – Create custom pipeline views](https://help.folk.app/en/articles/6044821-create-custom-pipeline-views), read 2026-08-24).

**3.3 What the column header sums.** Folk is the clearest: "By each column there is a number counter showing by default the number of cards in that column, **but you can change this by selecting the counter**" — swap it to a sum over a numeric field to "get the sum of your deals value" ([Folk – Create custom pipeline views](https://help.folk.app/en/articles/6044821-create-custom-pipeline-views), read 2026-08-24). Attio: collapsed columns show "stage color, name, and record count", and "Add calculation" at the stage bottom does numeric aggregates ([Attio kanban](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views), read 2026-08-24). Twenty stores the choice as **view metadata** — `kanbanAggregateOperation` + `kanbanAggregateOperationFieldMetadataId` on `ViewEntity`, rendered by `RecordBoardColumnHeader` alongside a `RecordGroupChip`, using the same twelve `AggregateOperations` as the table footer ([RecordBoardColumnHeader.tsx](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-board/record-board-column/components/RecordBoardColumnHeader.tsx), read 2026-08-24). Pipedrive: hovering a stage name reveals that stage's total value, the "i" icon next to the pipeline selector shows a whole-pipeline summary, and the top of the view shows both **total value and total weighted value** ([Pipedrive help, read 2026-08-24](https://support.pipedrive.com/)). HubSpot: column headers auto-update record counts and, for Deals, **Total and Weighted amount**, with "a brief 'delay' icon… while weighted totals… recalculate"; deal amounts are abbreviated by default (≥$1M → "$1M") with a **"Show formatted amounts on the board"** toggle for exact figures; a data-insights card shows total, average and weighted deal amount ([HubSpot – Manage records in board view](https://knowledge.hubspot.com/records/manage-records-in-board-view), read 2026-08-24). Close shows **value, not count**: each column shows "the actual annualized value of Opportunities broken down by Status", configurable to one-time/monthly/annual and toggleable between raw Value and **Expected Value (Value × Confidence)**, and can include or exclude Won/Lost ([Close – Opportunity pipeline view](https://help.close.com/docs/opportunity-pipeline-view), read 2026-08-24); whether a count also shows is `UNVERIFIED`. Salesforce Kanban configures grouping and a **"Summarize By"** numeric field (sum/count/average) behind a **wrench icon**, and roll-up-summary and formula fields are ineligible as the summarised field ([Trailhead, read 2026-08-24](https://trailhead.salesforce.com/)). Linear boards: no documented per-column sum or count badge — `UNVERIFIED`.

**3.4 Board sizing and pagination, from Twenty's constants** ([record-board/constants/](https://github.com/twentyhq/twenty/tree/main/packages/twenty-front/src/modules/object-record/record-board/constants), read 2026-08-24): `RECORD_BOARD_COLUMN_WIDTH = 200`, `RECORD_BOARD_COLUMN_MIN_WIDTH = 150`, `RECORD_BOARD_COLUMN_MAX_WIDTH = 400`, `RECORD_BOARD_QUERY_PAGE_SIZE = 10` (columns paginate — a board is not one big fetch), and a constant literally named `RECORD_BOARD_FETCH_MORE_THROTTLING_WAIT_TIME_IN_MILLISECONDS_TO_AVOID_REACT_FREEZE = 50`. Column width is persisted per view (`ViewEntity.kanbanColumnWidth`), added by a dedicated upgrade migration.

**3.5 Drag mechanics and multi-card drag.** Twenty uses **`@dnd-kit/react` ^0.3.2** (not react-dnd, not @hello-pangea/dnd) ([twenty-front package.json](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/package.json), read 2026-08-24). Its `useRecordBoardDndKit` captures, on drag start, the dragged record id **and all currently multi-selected record ids** — so dragging a card that is part of a selection drags the whole selection; `resolveDropFromPointer` computes a live drop index for the insertion indicator; on cancel it calls `resetDragState` ([useRecordBoardDndKit.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-board/record-board-dnd/hooks/useRecordBoardDndKit.ts), read 2026-08-24). Attio does the same at the product level: hover reveals checkboxes, shift-click selects a range, and "You can then drag and drop selected cards to move them into a new stage simultaneously" ([Attio kanban](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views), read 2026-08-24). Folk offers a **keyboard** equivalent: `Option/Alt+←→` moves cards across columns, `Space` opens the card, `Cmd/Ctrl+A` selects all cards in a column, `Shift+↑↓` selects multiple within a column, `Cmd/Shift+select` across columns ([Folk shortcuts](https://help.folk.app/en/articles/5007580-what-are-folk-shortcuts), read 2026-08-24).

**3.6 The sort-versus-manual-order conflict — the mechanic almost every naive board misses.** Twenty's drop handler references `RECORD_INDEX_REMOVE_SORTING_MODAL_ID` and `currentRecordSortsComponentState`: if the view has an active sort, manually reordering cards is meaningless, so **Twenty opens a confirmation modal offering to remove the sort** before persisting the manual order ([useRecordBoardDndKit.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-board/record-board-dnd/hooks/useRecordBoardDndKit.ts), read 2026-08-24). Linear solves the same problem by rule rather than dialog: manual ordering requires Grouping = No grouping and Ordering = Manual, and board and list **share one ordering state** ([Linear – Display options](https://linear.app/docs/display-options), read 2026-08-24).

**3.7 What happens on drop.** Linear: "when you move issues to a new column on a board, it will go to the top if you make the change with the keyboard shortcut `S` or command menu and **to wherever you placed it if you used the mouse**"; `Option/Alt+Shift+↑/↓` moves to top/bottom of the column ([Linear – Board layout](https://linear.app/docs/board-layout), read 2026-08-24). HubSpot: **moving a card into a stage with required properties pops a small form** — "enter or select a property value, then click Next" — before the move commits, then re-sorts the destination column per the view's sort criteria ([HubSpot – Manage records in board view](https://knowledge.hubspot.com/records/manage-records-in-board-view), read 2026-08-24). Close: drop updates status; **dragging to the bottom of the Pipeline View marks Won or Lost** ([Close – Opportunity pipeline view](https://help.close.com/feature-guide/opportunities/opportunity-pipeline-view), read 2026-08-24). Attio/Folk/Airtable/Notion: the status field just updates, immediately, with **no confirmation and no lost-reason prompt documented** for any of them.

**3.8 Mandatory lost reason exists in exactly one of these products natively.** Pipedrive: marking a deal Lost **triggers a prompt**; with predefined lost reasons enabled (Company settings → Lost reasons → "+ Lost reason", deals-admin only) the prompt shows a dropdown plus a free-text comment, and "Mark as lost" commits, after which the reason is visible on the deal ([Pipedrive – Lost reasons](https://support.pipedrive.com/en/article/lost-reasons), read 2026-08-24). Salesforce is **not** mandatory out of the box — making it required is done with a validation rule or trigger; and via the Path, if the configured reason is "Other (explain)" the user cannot complete the transition through the Path at all (`UNVERIFIED` at verbatim level, corroborated across community sources, read 2026-08-24). HubSpot has a "Closed Lost Reason" property teams mark required themselves; a hardcoded platform prompt is `UNVERIFIED`. Attio, Folk and Close document none.

**3.9 Rotting / time-in-stage.** Pipedrive's is the fullest spec: per-stage **"Rotting in (days)"** toggle set via the pipeline pencil icon (**no default — an admin must pick a number per stage**); the card tile "turns progressively darker shades of **yellow through red**" the longer it sits; the timer **resets** on marking an activity done, adding notes/files, sending/receiving/unlinking/deleting an email, or editing deal details; and the documented gotcha — **rotting ignores the Next Activity date**, so a deal with a far-future scheduled activity still rots ([Pipedrive – The Rotting feature](https://support.pipedrive.com/en/article/the-rotting-feature), read 2026-08-24). Attio has "Time-in-stage tracking with customizable target durations (displays red when exceeded)" and a **confetti animation** when cards reach specific stages, plus a "Track time in stage" label in list settings ([Attio kanban](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views) and [Attio – Understanding lists](https://attio.com/help/reference/attio-101/attios-data-model/understanding-lists), read 2026-08-24). Close's **Pipeline Guidance** flags opportunities where "the estimated closing date has passed", "the opportunity has stalled… longer than expected", or "a lead has recently contacted you, but your team hasn't responded", surfaced behind a **"Needs attention" toggle** with suggested next actions and daily Inbox reminders ([Close – Opportunities](https://help.close.com/docs/opportunities), read 2026-08-24).

**3.10 Collapsing.** Attio: "Collapse columns"/"Expand columns" (collapsed shows only stage identifier and count), "Collapse cards"/"Expand cards" (names only vs full), and per-stage "Hide stage"; the June 2026 release summarised it as "Kanban boards are cleaner and more compact, with collapsible columns and cards, hidden empty fields, and refreshed styling" ([Attio kanban](https://attio.com/help/reference/managing-your-data/views/create-and-manage-kanban-views) and [Attio changelog 29 Jun 2026](https://attio.com/changelog/2026/changelog-june-29-2026), read 2026-08-24). Linear hides a column via the column's three-dot menu → **Hide**, which moves it to last position and keeps it draggable back ([Linear – Board layout](https://linear.app/docs/board-layout), read 2026-08-24). HubSpot columns collapse via a caret. Twenty stores `shouldHideEmptyGroups` on the view.

**3.11 Two-dimensional boards (swimlanes).** Linear: Display options → grouping by **Rows** turns the board into a grid — e.g. rows = Project Status, columns = Target date by quarter — for "a high-level overview of the roadmap by quarter or team" or "resource allocation across members of your team"; `T` collapses/expands a row and `⌥←`/`⌥→` moves a card across swimlane columns ([Linear changelog – Swimlanes](https://linear.app/changelog/2024-04-03-swimlanes), read 2026-08-24). Airtable explicitly cannot do this.

**3.12 Probability and weighted value.** Pipedrive: every stage defaults to **100%** probability until an admin changes it; if only a *deal-level* probability is set, weighted = value × deal%; if only *stage-level*, value × stage%; if both, **deal-level wins**; if neither, weighted = full value — and these feed the **Forecast** view ([Pipedrive – Probability](https://support.pipedrive.com/en/article/probability-in-pipedrive), read 2026-08-24). Close computes "Expected Value… by multiplying Value X Confidence", caps at **1000 Opportunities per Lead**, requires each pipeline to have at least one **Active**, one **Won** ("add the value as revenue in Reporting. This Status cannot be removed") and one **Lost** ("removes the value from any expected revenue") status, and supports separate pipelines for different products sold to the same lead ([Close – Opportunities](https://help.close.com/docs/opportunities) and [Opportunity statuses](https://help.close.com/docs/opportunity-statuses), read 2026-08-24).

### 4. Navigation

### 5. Density and information hierarchy

**5.1 The Linear thesis: one good default, not infinite configuration.** From the Figma writeup of the Linear Method: *"We design it so that there's one really good way of doing things"* and *"there may not be one right way to do something in Linear, but there is a default way"* ([The Linear Method](https://linear.app/method) and [Figma blog](https://www.figma.com/blog/the-linear-method-opinionated-software/), read 2026-08-24). This is why Linear has curated Display Properties instead of an Airtable-style generic table builder, and why cards never show descriptions. Their craft essay makes the latency argument explicitly: *"One small thing that you won't see or think about but will hopefully feel is a detail we designed"*, and on submenu hover geometry — *"It may only take a fraction to 1–2 seconds longer to move your mouse in an upside down L shape but the seconds add up when you're taking the action multiple times"* — built in "about 40 lines of code all in all" ([linear.app/now/invisible-details](https://linear.app/now/invisible-details), read 2026-08-24). Their founding framing: existing tools "were built for management" while individual contributors disliked them, so speed for the IC is the axis ([Pragmatic Engineer interview](https://newsletter.pragmaticengineer.com/p/linear), read 2026-08-24). I searched for a Linear post literally titled "Building for speed" and did not find one — treat that title as a third-party paraphrase, `UNVERIFIED`.

**5.2 Attio's density lever is many narrow saved views, not one dense table.** Per-view column visibility and relabelling, six-attribute highlight cap, "Hide empty attributes" on kanban cards, compact/standard toggle on embedded lists, automation events collapsed by default, and a per-object remembered timeline filter (all cited in §1–§3). Two more: **"Dark mode is properly dark now, with stronger contrast, better accessibility, and a leaner, more predictable palette"** and **"Popovers, dialogs, and dropdowns now use refined elevated-surface styling in dark mode"** ([Attio changelog 29 Jun 2026](https://attio.com/changelog/2026/changelog-june-29-2026) and [28 Jul 2026](https://attio.com/changelog/2026/changelog-july-28-2026), read 2026-08-24) — i.e. dark mode is expressed as *elevated surfaces*, not shadows.

**5.3 Salesforce's density mechanism has a name, and it is the Compact Layout** (see 2.3). Its list-view lever is "Select Fields to Display". I found **no** global compact/comfortable density toggle in Salesforce — `UNVERIFIED as absent`.

**5.4 HubSpot layers per-user over admin default.** Individual users can rearrange and hide sidebar property cards and board-card properties **for themselves only**; Super Admins set the account-wide default via Settings → Objects → Record Customization. Concrete caps: the "About this [record]" card holds up to **50 properties**; board cards default to **4 properties, extendable to 6**, and a property with no value on a record simply does not render on that card ([HubSpot – Customize the properties shown on records](https://knowledge.hubspot.com/object-settings/customize-properties-in-record-sections) and [Customize the updated board cards](https://knowledge.hubspot.com/records/customize-the-updated-board-cards), read 2026-08-24).

**5.5 Close hides most of the pipeline on purpose.** The Inbox is an explicitly filtered daily work surface rather than the lead list; Pipeline Guidance's "Needs attention" toggle surfaces only flagged deals; pinned activities cap at 5 atop a long feed; and the 2025 lead-page redesign targeted "improved information hierarchy" with a claimed 40% speed gain ([Close – Inbox](https://help.close.com/docs/inbox), [Opportunities](https://help.close.com/docs/opportunities), [2025 features](https://close.com/blog/close-features-sell-smarter-2025), read 2026-08-24).

**5.6 Twenty's actual token values** (all read 2026-08-24 from [packages/twenty-ui/src/theme/constants/](https://github.com/twentyhq/twenty/tree/main/packages/twenty-ui/src/theme/constants)):

### 6. Empty states, loading states, and onboarding

**6.1 Empty states should be plural, keyed by cause.** Twenty ships **five** distinct ones, dispatched by `RecordTableEmptyState.tsx`: read-only (user lacks update permission), remote (object is a synced non-native object), soft-delete (the "show deleted" filter is on and there are none), no-records-at-all, and no-record-found-for-filter ([RecordTableEmptyState.tsx](https://github.com/twentyhq/twenty/blob/main/packages/twenty-front/src/modules/object-record/record-table/empty-state/components/RecordTableEmptyState.tsx), read 2026-08-24). For the truly-empty case the button label is generated as `` `Add a ${objectLabelSingular}` `` with an `IconPlus`, an `animatedPlaceholderType="noRecord"` illustration, and — importantly — the CTA calls `useCreateNewIndexRecord`, **creating an inline row directly rather than opening a form**.

**6.2 SLDS specifies empty-state illustrations dimensionally.** The Illustration component pairs an `aria-hidden` SVG with a **mandatory heading**, optional body, optional CTA; **base = max-width 300px / max-height 200px, large = 600px / 400px**; recommended line length ≤66 characters; documented categories informational, no-data, error, custom, misc; and the stated rationale is *"Empty state is an opportunity to engage and delight users."* ([SLDS illustration](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/illustration/docs.mdx), read 2026-08-24).

**6.3 Loading: spinners vs skeletons is an explicit choice.** SLDS: spinners are "preferred over stencils for initial parent-component loads", require a `position: relative` parent (`.slds-is-relative`), come in xx-small through large plus inverse/brand, need `role="status"` + assistive text, and — the useful bit — have a **"Delayed" variant to control when the spinner appears**, avoiding flash-of-spinner on fast loads ([SLDS spinners](https://raw.githubusercontent.com/salesforce-ux/design-system/master/ui/components/spinners/docs.mdx), read 2026-08-24). Twenty uses skeletons: `isRecordTableInitialLoadingComponentState`, plus `RecordBoardColumnCardContainerSkeletonLoader` and `RecordBoardColumnLoadingSkeletonCards` for the board (read 2026-08-24). Attio's own virtualization library exposes exactly this distinction as props on `ReactDataList.Fetchable`: **`renderPendingRows`** (skeleton rows), **`renderPending`** (full-screen spinner), `renderError`, throwing a Suspense signal while loading ([Attio – React Data List](https://attio.com/engineering/blog/react-data-list-building-virtualized-uis-declaratively), Sep 2025, read 2026-08-24).

**6.4 Linear's answer to loading states is architectural: don't have any.** Their sync engine "manages data replication across clients, networking, error handling, offline mode and transactions", and that early investment "makes it possible to create even complex new features without backend engineering" ([linear.app/now/scaling-the-linear-sync-engine](https://linear.app/now/scaling-the-linear-sync-engine), read 2026-08-24). The deeper technical claims (IndexedDB as the read source, local-first mutations, WebSocket-pushed deltas) come from secondary breakdowns ([performance.dev](https://performance.dev/how-is-linear-so-fast-a-technical-breakdown), [wzhudev/reverse-linear-sync-engine](https://github.com/wzhudev/reverse-linear-sync-engine), read 2026-08-24) and are `UNVERIFIED` against Linear's own prose. Attio states the same goal in its own words: *"a seamless editing experience that allows updates on the client without blocking on round trips to the server, and supports offline syncing and real-time collaboration"* ([Attio engineering – Where's the technical challenge in CRM anyway?](https://attio.com/engineering/blog/where-s-the-technical-challenge-in-crm-anyway-), Nov 2025, read 2026-08-24). A named undo-toast rollback convention for Linear is `UNVERIFIED` — widely attributed to them, not documented by them.

**6.5 Virtualization is the load-bearing table technique, and building the row array is the hard part.** Attio's write-up of the problem: constructing the flat data array becomes "a cumbersome mess, often a single hook that's a thousand lines long". Their answer, `react-data-list`, lets `ReactDataList.Row` / `.Rows` register item objects with render functions and **recycler types**, so "these components are totally unaware of the wider list, so it can be dropped in and reused in any other data list"; outcome claim, "It's made it easy to build virtualization into pretty much every screen, which has made a night and day difference to our app's performance" (no numbers) ([Attio engineering](https://attio.com/engineering/blog/react-data-list-building-virtualized-uis-declaratively) and [attio/react-data-list](https://github.com/attio/react-data-list), read 2026-08-24). For our stack the equivalent is TanStack Table's pinning state (columns split into left/center/right, sticky CSS applied) plus its virtualization guide ([TanStack column pinning](https://tanstack.com/table/v8/docs/guide/column-pinning), [sticky pinning example](https://tanstack.com/table/v8/docs/framework/react/examples/column-pinning/sticky), [virtualization](https://tanstack.com/table/latest/docs/guide/virtualization), read 2026-08-24). Attio's scale context: "reduced tail latency by up to 10x across all request types", called out for "data-heavy views, large workspaces, and dense record pages" ([Attio changelog – Performance improvements](https://attio.com/changelog/2026/performance-improvements), 29 Apr 2026, read 2026-08-24), against "in excess of 250,000 events per minute" at peak ([Attio engineering](https://attio.com/engineering/blog/where-s-the-technical-challenge-in-crm-anyway-), read 2026-08-24).

**6.6 Import wizards are a multi-step flow with dedupe built in, not a file input.**
- **Attio**: Import/Export → Import CSV → **Map Attributes** (with inline "+ Create new attribute") → **Review Values** (flags inconsistencies) → **Preview Import** → **Start import**. Dedupe uses per-object unique identifiers — **domain for Companies, email for People**: "If a record with a matching unique attribute value is found in Attio, it will be updated with the new values from your file. If no match is found, a new record will be created" ([Attio – Import data via CSV](https://attio.com/help/reference/imports-exports/csv-imports/import-data-into-attio-via-csv), read 2026-08-24). A small but telling fix: "The importer now skips blank records, so you don't end up with empty rows to delete later" ([Attio changelog 29 Jun 2026](https://attio.com/changelog/2026/changelog-june-29-2026), read 2026-08-24).
- **Close**: field-mapping dropdowns "turn from blue to green once you've matched a spreadsheet column to a field in Close"; sample-row preview; skip individual columns or "Skip All Unassigned Columns"; custom fields auto-map from a `custom.` column-header prefix; an options step with opt-in dedupe on chosen fields and, on match, a choice of **fill-blanks-only / full-replace ("cannot be undone") / skip**, and for non-matches create-new or skip; pre-import validation flags invalid cells **in yellow** with a "Review" action; failed rows download as a CSV with a "Validation Errors" column, retained **30 days** ([Close – Importing leads from file](https://help.close.com/docs/importing-leads-from-file), read 2026-08-24).
- **Pipedrive**: mapping with extra sub-steps for multi-option/address/phone fields; duplicates can be **merged rather than created**; mapping the **Pipedrive System ID** column makes a re-import *update* instead of duplicating; the post-import summary reports **added / updated / merged / skipped** counts ([Pipedrive import help, read 2026-08-24](https://support.pipedrive.com/)).
- **Folk**: two-column mapping with auto-suggested matches; unmatched columns become text fields, transformable afterwards into tags/dates/numbers; hard limits **25,000 rows / 200 columns / 2,560 characters per field**, up to 5 minutes processing; "Import people"/"Import companies" buttons appear **when the group is empty** ([Folk – Import contacts from a file](https://help.folk.app/en/articles/5865891-import-contacts-from-a-file), read 2026-08-24).
- **Close CRM migration** additionally offers a **"Start Sample Migration"** button that runs a trial import via Import2 and emails when the sample completes ("could take a few hours") ([Close – Migration from another CRM](https://help.close.com/docs/migration-from-another-crm), read 2026-08-24).

### 7. What a CRM has that a naive implementation misses

**7.1 Per-relationship attributes (Attio's "list entry").** Adding a record to a list creates a **list entry** — "an instance of that record within the list, and it's where list-specific attribute values are stored". Two attribute classes exist: object attributes on the record (Name, Email) and **list attributes on the entry** (Stage, Applying for, Hiring manager). A table row *is* a list entry, a kanban card *is* a list entry, and **the same record can appear more than once in one list** — "if the same person applies for two different roles, they can have two separate entries in a Recruiting list" ([Attio – Understanding lists](https://attio.com/help/reference/attio-101/attios-data-model/understanding-lists) and [Define your data model](https://attio.com/help/reference/attio-101/attios-data-model/define-your-data-model-objects-lists-and-views), read 2026-08-24). Attio's standard objects: Companies, People, Deals, Workspaces, Users — Companies and People on by default. Airtable's List view generalises this to a nested hierarchy **up to 10 layers deep** (3 levels of linked-table nesting + 7 same-table), with a blue highlight marking valid drop targets ([Airtable – List view](https://support.airtable.com/docs/list-view-overview), read 2026-08-24).

**7.2 A real field-type system, including composites.** Twenty's `FieldMetadataType` has **25** members: `ACTOR, ADDRESS, ARRAY, BOOLEAN, CURRENCY, DATE, DATE_TIME, EMAILS, FILES, FULL_NAME, LINKS, MORPH_RELATION, MULTI_SELECT, NUMBER, NUMERIC, PHONES, POSITION, RATING, RAW_JSON, RELATION, RICH_TEXT, SELECT, TEXT, TS_VECTOR, UUID` ([FieldMetadataType.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-shared/src/types/FieldMetadataType.ts), read 2026-08-24). The **composite decomposition is the part to copy** ([CompositeFieldTypeSubFieldsNames.ts](https://github.com/twentyhq/twenty/blob/main/packages/twenty-shared/src/constants/CompositeFieldTypeSubFieldsNames.ts), read 2026-08-24):
```
CURRENCY:  { amountMicros, currencyCode }
EMAILS:    { primaryEmail, additionalEmails }
LINKS:     { primaryLinkUrl, primaryLinkLabel, secondaryLinks }
PHONES:    { primaryPhoneCallingCode, primaryPhoneCountryCode, primaryPhoneNumber, additionalPhones }
FULL_NAME: { firstName, lastName }
ADDRESS:   { addressStreet1, addressStreet2, addressCity, addressState,
             addressCountry, addressPostcode, addressLat, addressLng }
ACTOR:     { source, name, workspaceMemberId, context }
RICH_TEXT: { blocknote, markdown }
```
Note **money as `amountMicros` (integer × 1,000,000) plus a separate currency code**, sub-fields individually filterable and sortable, and `ACTOR` as a structured "who did this and from where" rather than a plain `createdBy` FK. `RelationType` is only `MANY_TO_ONE | ONE_TO_MANY` — many-to-many is composed, and polymorphism is a separate `MORPH_RELATION`. Retool's Table separately documents ~25 *display* formats (String, Multiline string, Email, Phone, HTML, Markdown, JSON, Number, BigInt, Currency, Percent, Progress, Rating, Date, Datetime, Time, Avatar, Image, Icon, Tag, Tags, Button, Link, Boolean) plus computed custom columns via `{{ item }}` / `{{ currentRow }}` ([Retool columns](https://docs.retool.com/apps/guides/data/table/columns), read 2026-08-24).

**7.3 Formula / rollup fields.** Attio shipped formula attributes in July 2026, built on a custom language using the **Lezer** incremental parser with its own syntax highlighting inside CodeMirror, a declarative type system covering record attributes and complex types (actor references, phone numbers), server-side batched execution across millions of records with some functions "expressed in SQL, which allows us to offload the execution onto Google's Spanner", the write side of their data model rebuilt as a Rust service emitting change events through PubSub so **formulas subscribe to those events and recompute on dependency change**, plus an AI formula builder that uses the type system to "enforce correctness of the output" and an "auto fix" for errors ([Attio engineering – How we built formula attributes](https://attio.com/engineering/blog/how-we-built-formula-attributes), Jul 2026, read 2026-08-24). Salesforce's roll-up summaries support exactly four aggregates — **Count, Sum, Min, Max** — Sum only over Number/Currency/Percent, Min/Max also over Date/DateTime, and **formula fields cannot be rolled up** without first being copied into a plain field (search-aggregated Trailhead/Salesforce, read 2026-08-24).

**7.4 Duplicate detection and merge — and how differently vendors treat it.**
- **Salesforce** splits it in two: **Matching Rules** (Exact / Fuzzy [Levenshtein/phonetic] / custom multi-field) and **Duplicate Rules** (**Alert** = warn but allow, **Block** = prevent save, **Bypass for API** = enforce in UI only). A duplicate rule references up to **3 matching rules**; an object may have up to **5 active matching rules** (search-aggregated help.salesforce.com, read 2026-08-24).
- **HubSpot** compares contact/company property values **daily**, surfaced at Contacts/Companies → **Actions → Manage Duplicates** (Pro/Enterprise), showing up to **10,000 duplicate pairs**, mergeable or rejectable individually or in bulk, with custom matching rules. Its **merge conflict rules are the most precisely documented anywhere**: the **primary record's non-empty values win**; blanks fall through to the secondary; **contact emails and company domains are both kept** (secondary becomes an alternate); **lifecycle stage** keeps whichever is "furthest down the funnel"; **form submissions and analytics are summed**, not overwritten; **legal-basis/consent** keeps the most recent from either. A record **cannot be merged once it has 250+ prior merges**; a merge is blocked if it would exceed association limits; associations from both carry over but only the primary's primary-company keeps the Primary flag; **merging is irreversible** — "it is not possible to unmerge them"; and merge history (pre-merge values + timestamp) is exportable **for up to 90 days** ([HubSpot – Merge records](https://knowledge.hubspot.com/records/merge-records), read 2026-08-24).
- **Attio** auto-detects by **domain for companies and email for people**; flow is record → **⋮ → Merge Records → + to search/select → optionally swap left/right → "Merge records"**, and "The data for the record on the right will be prioritized and merged to", combining "all data including list entries, notes, tasks, and comments". Manual merge is **Company and Person only** — not Deals, Users, Workspaces or custom objects — there is no native bulk merge, and deletion is final: "once a record is deleted, it cannot be recovered by you or your team" ([Attio – Merge and delete records](https://attio.com/help/reference/managing-your-data/records/merge-and-delete-records), read 2026-08-24).
- **Folk** has three tiers: **auto-merge on import** (exact match — people on "first name + last name + email, OR first name + last name + phone number" or matching social URLs; companies on "Name (case sensitive) + LinkedIn"), a **Duplicates view** of suggested merges with stated detection reasons, "merge all", "Don't merge" dismissal and reason filters, and **manual merge** of 2+ selected contacts — with granular control over which emails/companies/phones survive and star-marking the primary value ([Folk – Clean & manage duplicates](https://help.folk.app/en/articles/5007403-clean-manage-duplicates), read 2026-08-24).
- **Close has no in-app merge at all.** Users run scanners at `support-tools.close.com` with their own API key, producing CSVs for **Lead Duplicates** (name/phone/email org-wide) and **Contact Duplicates** (within a lead) that "produce downloadable CSV files without modifying your account" — and **the merge itself is executed by Close Support** after review. Winner rules: earliest-created, most-recently-status-changed, or highest-priority-status-per-pipeline ([Close – Finding and merging duplicates](https://help.close.com/getting-started/import-data-into-close/finding-and-merging-duplicates), read 2026-08-24).

**7.5 Email sync and thread matching is a matching problem, not a sync problem.** Attio: "Attio links emails to records based on the participants on the email. For person records, an email appears when a participant's email address matches an email address on the record. For company records, an email appears when a participant's email address has a **domain** that matches a domain on the company record." It auto-creates a person record "for every email address involved, **including people cc'd**", and companies from domains — with a Feb 2026 toggle to "Disable automatic company record creation from email addresses in Settings > Workspace" and a way to see the results: **"Filter by `Created by` > ⚙️ System on any view"** ([Attio – View emails and meetings](https://attio.com/help/reference/email-calendar/view-emails-and-meetings), [Introduction to email sync](https://attio.com/help/reference/attio-101/syncing-people-and-companies), [changelog 25 Feb 2026](https://attio.com/changelog/2026/changelog-february-25-2026), read 2026-08-24). Sequence reply-matching is stricter: "the reply needs to come from the address that was enrolled and arrive on the same email thread Attio sent to."
Close: connecting via IMAP/SMTP "will auto-log any email that appears in your Sent folder — regardless of how it was sent", attaches mail "to a lead where a matching email address is present as part of the contact", and — the good bit — "**Close also associates replies to emails coming from a different email address.** When you email a lead and get a reply from a different email address, the reply will be associated with your lead, so you don't need to forward it to Close manually"; plus a per-org secret BCC address where the sender must already be linked, to prevent spoofing (search-synthesised Close help, read 2026-08-24). At the API level "an email thread is created when an email is synced and it doesn't match any of the existing threads" ([Close event log](https://developer.close.com/resources/event-log/list-of-events/), read 2026-08-24).
HubSpot: BCC'ing the personal address **logs** mail but gives **no open/click tracking** (that needs the connected-inbox send path with its pixel); **CC'ing a new address creates a new contact, BCC'ing does not** ([HubSpot BCC/forwarding help, read 2026-08-24](https://knowledge.hubspot.com/)).
Folk's sync exclusion list is worth copying verbatim as a spec: Gmail import excludes unread, draft/junk/trash/chat, group-address mail, system notices, **emails with 20+ recipients**, and subscription/mailing-list mail; calendar sync excludes declined events, **20+ attendee events**, and daily/weekly recurring events, retroactively removing cancelled/declined ones; **3-year lookback**; and it is **read-only** — "actions taken in Folk don't reflect back to Gmail or Outlook" ([Folk – FAQ Sources](https://help.folk.app/en/articles/8170484-faq-sources-integrations), read 2026-08-24).

**7.6 Derived "last contacted" fields.** Attio auto-populates **Last interaction** ("the most recent interaction any workspace member had with the record"), First interaction, **Connection strength**, **Strongest connection**, Emails, plus per-channel variants; calendar-based attributes "use the event's start time, not its end time" (moderate confidence, search-synthesised, read 2026-08-24). Folk's smart fields: "My Last interaction, My total interactions, Team Last interaction, Last interaction by, Strongest connection, Groups", where "Last Interaction" auto-updates "anytime you email, message, or meet a contact" and "Strongest Connection… will only be calculated if you have teammates in your workspace **and if they have shared their interactions**" ([Folk data model](https://help.folk.app/en/articles/9790806-folk-data-model), read 2026-08-24). Pipedrive's **"Next activity date"** always reflects the earliest incomplete scheduled activity and updates live; separately a **"marked as done time"** is stored distinct from the original **"due date"**, so retroactive logging does not rewrite history ([Pipedrive – Activities](https://support.pipedrive.com/en/article/activities), read 2026-08-24). Close notably has **no** canonical "Last Contacted" field — the documented pattern is filtering Smart Views against raw activity dates ("Days ago" call filters) — `UNVERIFIED` as a named field.

**7.7 Activity types are enumerated, and calls/notes/tasks are not the same thing.** HubSpot's defaults: **Calls** (direction, duration, recording), **Emails** (sender/recipient, opens, clicks), **Meetings** (attendees, location, outcome), **Notes**, **Tasks** (due date, priority, completion), plus **Communications** (SMS/WhatsApp/LinkedIn) and **Postal mail** ([HubSpot default activity properties, read 2026-08-24](https://knowledge.hubspot.com/)). Pipedrive ships six built-ins — **call, meeting, task, deadline, email, lunch** — plus custom types, with cascade rules: an activity on a **deal** auto-links to that deal's person and organisation; on a **person** auto-links to their organisation; on an **organisation** alone stays unlinked to any person or deal ([Pipedrive – Activities](https://support.pipedrive.com/en/article/activities), read 2026-08-24). Close distinguishes **Lead Tasks** from **Call Tasks**, where a Call Task "auto-complete[s] only when a Call between the associated Contact and an assigned User" is logged — **marking it done is not enough** — and its guidance is to use Tasks for "unique actions that are not in your normal workflow" and Smart Views for recurring cadences ([Close – Tasks](https://help.close.com/docs/tasks) and [Call Tasks changelog](https://www.close.com/changelog/call-tasks), read 2026-08-24). Close's **call dispositions**: Abandoned, Answered, Blocked, Busy, Error, No answer, Directed to voicemail, Left a voicemail ([Close – Calling feature guide](https://help.close.com/feature-guide/calling), read 2026-08-24).

**7.8 Notes vs tasks vs reminders.** Attio Notes have no due-date mechanism; Tasks are the reminder primitive and accept **natural-language dates** — "call Tuesday at 7pm", "follow up next week", "check-in in September" ([Attio – Introduction to tasks](https://attio.com/help/reference/attio-101/productivity/introduction-to-tasks), read 2026-08-24). Folk splits them explicitly: Notes are default-**shared** with a private toggle before posting (switchable after via the 3-dot menu), reply-threaded, rich text with attachments; **Reminders** are the structured follow-up — Title (defaulting to "Reminder on _contact's name_"), Due date, Repeat (daily/weekly/monthly/quarterly/yearly), Assignment, Visibility — signalled by **a clock icon on the contact row**, with overdue ones rendered "in light grey" ([Folk – Adding notes](https://help.folk.app/en/articles/5007332-adding-notes) and [Set reminders](https://help.folk.app/en/articles/5658439-set-reminders-on-your-contacts), read 2026-08-24).

**7.9 Sequences / cadences.** Attio: sequence canvas with **Wait** steps ("minimum of 1 day"), first email defaulting to 0 days ("sent the day a recipient is enrolled"), sending hours, exit criteria, delegated sending ([Attio – Create a sequence](https://attio.com/help/reference/automations/sequences/create-a-sequence), read 2026-08-24). Folk: "up to 10 steps", multiple senders, "custom variables", a "Magic Field" for AI personalisation beyond first-name tokens, and analytics for "delivered, bounced, replied to, and clicked"; reply tracking requires the sender be a synced account ([Folk – Send email sequences](https://help.folk.app/en/articles/8744016-send-email-sequences), read 2026-08-24). Close's **Workflows** is the most fully specified automation model found and reads like a requirements list: step types Email / SMS / Call Task / Update Lead / Create Opportunity / Task; delays **1 minute to 365 days** with weekends counting; a **Communication Window** defaulting to **Mon–Fri 9am–4pm recipient local time** with timezone priority (1) contact's manual local time, (2) estimate from area code/address, (3) fallback — whichever of delay and window resolves later wins; **org-level blackout dates** that suppress only automated email/SMS; enrolment manual or by event trigger (lead/contact/opportunity events including value thresholds, custom activity, call, meeting, form submission), each filterable; **Workflow Goals** that auto-pause on incoming email/SMS/call, meeting booked, status change or a defined outcome, counting as "converted"; **Run Once** (default where communication steps exist, preventing duplicate sends) vs **Run Multiple**; a "Manage Workflows" permission plus a per-user "Allow automated Workflows to send on your behalf" toggle; reporting on Goal Met %, Avg Time To Goal, Responded by Step; and **rate limiting that auto-pauses runs on a trigger surge and notifies the owner** ([Close – Workflows](https://help.close.com/docs/workflows), read 2026-08-24). Terminology caution: Close's API still exposes a **Sequences** resource while the help centre documents only **Workflows**, with no cross-reference — relationship `UNVERIFIED` ([developer.close.com sequences](https://developer.close.com/resources/sequences/), read 2026-08-24).

**7.10 Calling: power vs predictive dialer.** Close Power Dialer: "In a single click, the Power Dialer will automatically start calling through any saved Smart View, in the order the Leads appear", dialling "right after a call is completed" and auto-advancing on disconnect/busy/no-answer. Predictive Dialer dials multiple numbers simultaneously "behind the scenes", "detects when an actual human answers the phone and immediately routes an available sales rep to that call", discards voicemail/toll-free/busy without rep involvement, and "will adjust the automatic call rate continuously"; recommended at **10+ reps**, Scale plan only; abandoned calls play an org-level recorded message and are filterable by the "Abandoned" disposition; the session screen shows the Smart View being called, leads dialled so far, the org-wide predictive count for the day, **other users dialling the same view and their status**, and leads presently being dialled ([Close – Power & predictive dialing](https://help.close.com/docs/power-predictive-dialing) and [Using the Predictive Dialer](https://help.close.com/docs/using-the-predictive-dialer), read 2026-08-24). Call recording retention is plan-tiered: "30 days on Solo/Essentials, 90 days on Growth, indefinitely on Scale" ([Close – Calling feature guide](https://help.close.com/feature-guide/calling), read 2026-08-24). Close also documents a Smart View recipe for calling that is essentially a spec for a dialling queue: filter by current status → exclude leads called within N hours/days (they "re-enter the Smart View" once the interval passes) → exclude leads with an incomplete follow-up task ("there is not a Task matching Complete: No") → filter by **"Local time"** window (e.g. 9am–5pm) → filter to "Lead Owner: Me" → sort fewest calls first, then oldest call date ([Close – Creating Smart Views for calling](https://help.close.com/docs/creating-smart-views-for-calling), read 2026-08-24). Attio's native Call Intelligence "records, transcribes, and logs every call as you talk" across Google Meet, Zoom and Teams "right out of the box", auto-links recordings to records, does **not** auto-record internal calls (manual only), and gives a live transcript "with speaker labels and timestamps" — Pro/Enterprise only ([Attio – Call Intelligence](https://attio.com/platform/call-intelligence), read 2026-08-24).

**7.11 Enrichment, with honest hit rates.** Attio requires domain for Companies and email for People, links person↔company via "the domain of the first listed email address on the person's record page", enriches "within seconds of adding a new record" and continuously after; company fields include Name, Logo, Description, Categories, Location, **Estimated ARR**, Employee Range, Funding Raised, socials, Foundation date, Team, Twitter follower count; enriched cells render as **lilac cells with a sparkle icon in the column header** ([Attio – Enriched data](https://attio.com/help/reference/managing-your-data/enriched-data), read 2026-08-24). Folk waterfalls across "Apollo.io, People Data Labs, Clearbit, Datagma, Prospeo & DropContact" for Email, Phone, Company name, Job Title and URLs, from a group (up to **500 contacts**), a record, or the folkX LinkedIn extension; feedback is a **sparkle icon** on the far right whose hover shows a timestamp; credits are 500/month Standard and 1,000/month Premium, **1 credit per successful field with failures refunded** — and the docs state the hit rate plainly: **"Enrichments only work around 50-60% of the time."** ([Folk – 1-click Enrichment](https://help.folk.app/en/articles/6804416-1-click-enrichment-find-emails-phone-numbers), read 2026-08-24). Close's AI Enrich covers "LinkedIn URLs, industry, company size, physical address, sales team headcount" plus **custom-prompt-driven arbitrary fields** — "Need to enrich fields that are very specific to your business? Add a simple prompt and let AI Enrich tailor its search" — positioned as on-demand rather than "massive batch jobs" ([Close – AI Enrich](https://close.com/blog/ai-enrich-crm-data-entry), read 2026-08-24).

**7.12 Permissions are additive hierarchies, and lists/records need their own tier.** Attio: workspace roles **Admin** (can "view and manage all workspace objects, even without explicit access") and **Member**; object-level **Read only / Read and write / Full access**; **list-level four tiers** — Full access / Read and write / Read only / **No access**; **Teams** as reusable access-granting groups (Pro/Enterprise); and the resolution rule that matters — **"the most permissive grant always wins"** across workspace, team and individual settings. Plus plan gets workspace-level permissions only ([Attio – Manage members, admins, and teams](https://attio.com/help/reference/workspace-settings-billing/manage-members-and-admins), [Permissions in Attio](https://attio.com/blog/permissions-in-attio), [Manage access to lists](https://attio.com/help/reference/managing-your-data/lists/lists-access), and [changelog – Permissions](https://attio.com/changelog/2026/permissions) 18 Feb 2026, read 2026-08-24). Also note "records in object views are always visible to everyone in the workspace" while lists can be restricted ([Attio glossary](https://attio.com/help/reference/attio-101/attio-glossary), read 2026-08-24).
Pipedrive's **Visibility groups** are the clearest tiered model: on Lite/Growth, two choices per item type (**owner only** or **all company users**); on Premium and above, hierarchical custom groups with **four** tiers — owner only → owner's group members → owner's group + sub-groups → all company users — capped at **15 groups (Premium) / 25 (Ultimate) / 150 (Enterprise)**; each user belongs to exactly one group; deals-admin and global-admin bypass everything; groups can be blocked from specific **pipelines**; and individual records carry a **"Visible to"** override on top ([Pipedrive – Visibility groups](https://support.pipedrive.com/en/article/visibility-groups), read 2026-08-24). Salesforce's stack: org-wide defaults (often Private) → role hierarchy with a "Grant Access Using Hierarchies" toggle → sharing rules → territory sharing groups when Enterprise Territory Management is on (search-aggregated architect.salesforce.com, read 2026-08-24). Close ships four fixed roles — **Admin / Super User / User / Restricted User** — with **custom roles Scale-plan-only**, toggling permissions across Organization, Bulk actions, Leads (incl. Lead Visibility), Opportunities/Tasks/Activities, Communication and Enrichment, and **individual custom fields restrictable per role**; downgrading off Scale reverts users to Admin or Restricted User ([Close – Roles & permissions](https://help.close.com/docs/roles-permissions), read 2026-08-24).

**7.13 Assignment and round-robin.** Salesforce allows only **one active** Lead assignment rule and one Case rule per object, each an ordered list of entries (a Case rule supports up to **3,000 entries, including 300 formula entries**) evaluated top-down where **first match wins** — so a broad condition placed early starves the specific ones below it (search-aggregated help.salesforce.com "Guidelines for Assignment Rules", read 2026-08-24). Twenty ships workflow-driven assignment with **random / round-robin / least-loaded** strategies (~v2.16, mid-2026) ([twenty.com/releases](https://twenty.com/releases), read 2026-08-24; dates approximate). Close has a **"Slice query"** that splits a large lead list into non-overlapping portions for team distribution, plus a free companion tool **Robin** for round-robin ([Close – Lead assignment](https://help.close.com/docs/lead-assignment), read 2026-08-24).

**7.14 Soft delete, restore, and the absence of undo.** Pipedrive: deletion is soft; an individual deal restores from its own detail view via a top-right **Restore** button back into its original pipeline and stage; bulk restore lives at avatar → **Tools and apps → Restore data**, covering deals/leads/people/orgs/activities deleted in the **last 30 days**, admin-only, after which items are "permanently and irrecoverably deleted", and restoring brings back linked historical data ([Pipedrive restore-data help, read 2026-08-24](https://support.pipedrive.com/)). Twenty shipped soft delete with recovery in v0.24 (Aug 2024) and has a dedicated soft-delete empty state (see 6.1). Against that: **Attio has no undo** — a repeatedly-requested community gap: "Attio users have requested a Ctrl+Z/undo feature, particularly when editing cells… when users delete a Deal, dashboard, or report in Attio, it's gone permanently with no trash, draft, or way to undo it" ([Attio community – CTRL Z/Undo](https://www.attio.community/c/product-feedback/ctrl-z-undo-changes) and [Trash/undo for deleted dashboards](https://www.attio.community/c/product-feedback/trash-undo-for-deleted-dashboards-and-reports), read 2026-08-24). Folk documents deletion as permanent. Close's only documented undo is a toast-based undo-send in the Inbox. Salesforce's Recycle Bin exists but its retention figure could not be verified from a primary source this session (`UNVERIFIED`).

**7.15 Audit trails with real retention semantics.** Close's Event Log: "Most actions in Close that change an object are logged… creating a lead, sending an email, or deleting a note will create an event log entry", retained "up to 30 days back in history" via API, with "for privacy reasons, certain fields are only visible to non-admins for one hour". Each event carries `changed_fields`, `previous_data`, `data`, timestamps, user id (null for system actions), org/object ids, action type (`created`/`updated`/`deleted`/`merged`) and bulk-op metadata — **and rapid sequential edits consolidate into one event showing the net change**, e.g. a name going A→B→C collapses to `{"data": {"name": "C"}, "previous_data": {"name": "A"}}` while preserving the original `date_created` ([Close – Event Log](https://developer.close.com/resources/event-log/), read 2026-08-24). Salesforce's **Setup Audit Trail** (config changes, distinct from field history) retains **180 days** but shows only the 20 most recent rows in the UI (search-aggregated, read 2026-08-24). Attio adds historical **reporting** on top: "Historical values reports show how your data changes over time" at daily/weekly/monthly/quarterly/yearly intervals ([Attio – Historical values report](https://attio.com/help/reference/managing-your-data/dashboard-and-reports/set-up-a-historical-values-report), read 2026-08-24).

**7.16 @mentions gate on access.** Attio: "@" then a name inside a note/comment/task; mentioning notifies even on thread replies — **but "If someone is @mentioned in a list comment and they do not have access to the list, they will not receive a notification and will not be able to view the comment."** ([Attio – Comments and mentions](https://attio.com/help/reference/productivity-collaborating/comments-and-mentions), read 2026-08-24). Airtable auto-subscribes mentioned collaborators so they are "automatically notified of additional comments you make on that record, even when they are not directly mentioned", requires Commenter permission or higher, and logs comments into the activity feed and revision history ([Airtable help, read 2026-08-24](https://support.airtable.com/)). Linear's subscription model auto-subscribes on create/assign/mention, with `⇧S` to unsubscribe ([Linear – Inbox](https://linear.app/docs/inbox), read 2026-08-24).

**7.17 Lifecycle vs lead conversion — two different models.** HubSpot has **no Lead object and no conversion wizard**: contacts carry a lifecycle stage property with **8 defaults in order — Subscriber → Lead → Marketing Qualified Lead → Sales Qualified Lead → Opportunity → Customer → Evangelist → Other** — and progression is normally **forward-only automatically** ("default automatic updates… will only move the stage forward"; moving backward requires manually clearing the stage first). Updates come from a creation default, record associations (linking a Deal can auto-advance to Opportunity), integration syncs, or manual/bulk/import/workflow edits. Within SQL, a separate **Lead Status** property offers **New, Open, In Progress, Open Deal, Unqualified, Attempted to Contact, Connected, Bad Timing** ([HubSpot – Use lifecycle stages](https://knowledge.hubspot.com/), read 2026-08-24).

**7.18 Currency and dated exchange rates.** Salesforce's base multi-currency stores an ISO code + amount per record; **Advanced Currency Management** adds *dated* exchange rates where each rate has a start date and applies "until the day before the next start date", so a historical opportunity converts at the rate in force on its close date rather than today's — which is the difference between a forecast that reconciles and one that does not (search-aggregated Trailhead + help.salesforce.com, read 2026-08-24).

**7.19 Publishable / external views.** Folk: open a view → Share → **Publish view**, producing a public read-only URL that auto-updates on visitor refresh, excludes "Interactions, notes, reminders, Group assignments, Connection data", and lets visitors duplicate it into their own workspace — with the constraint "Currently, only table views can be published… Pipeline views can't be shared yet" ([Folk – Publish a view](https://help.folk.app/en/articles/6505030-publish-a-view), read 2026-08-24). Airtable's Interface Designer covers the internal equivalent, including a **Record review** layout — "designed to allow you to quickly switch between records with ease… useful for triaging or reviewing many records at once" — a left record list plus right detail with per-field **View-only** or **Editable** settings ([Airtable – Record review layout](https://support.airtable.com/articles/4384405105-airtable-interface-layout-record-review), read 2026-08-24).

**7.20 Small mechanics that signal a mature product.** Attio: right-click any record or chat to add it to a favourites folder; call recordings **auto-pin when you navigate away mid-playback** "so you never lose your place"; per-object-type avatar placeholder icons in light and dark mode; "Multi-select and delete tasks in bulk, handy when an import leaves a long list to clean up"; workspace exports include a `call_recordings.csv` under Settings > Export ([Attio changelogs 25 Feb / 29 Jun / 28 Jul 2026](https://attio.com/changelog), read 2026-08-24). Retool: per-row **hover action buttons** that "float to the right on row hover", **expandable rows** hosting "a repeatable set of components" via `currentRow`/`currentSourceRow` bindings, and a **"Group by"** toolbar button ([Retool table rows](https://docs.retool.com/apps/guides/data/table/rows), read 2026-08-24). Twenty: `RECORD_TABLE_ROW_DND_TYPE = 'record-table-row'` — rows are drag-reorderable, with a `rowDropLine` z-index tier for the insertion indicator.

## What this means for us

1. **Our table is an HTML `<table>` with `px-3 py-2` cells and links in the first column** (`src/components/ui/table.tsx`, `src/app/(app)/contacts/page.tsx`). Every product studied treats the grid as an application component with a focus model, a sticky first column, an aggregate footer and a trailing add-column affordance. Our design system already specifies "Rows 36px… header sticky" (`plan/08-design/design-system.md`) but the implementation has neither sticky header nor sticky column. Twenty's 32px + its published z-index tiers give us a ready-made spec.
2. **The first-column rule is free and high-value**: name click → open record, any other cell → edit, empty name cell → edit the name. We already navigate on name click; we just have no cell editing to contrast it with.
3. **Adopt the two-state focus model before adding inline editing.** Soft focus (arrow-navigable highlight) and edit mode must be separate state, with Enter/F2 to enter and Escape to exit and revert, per the ARIA grid pattern. Retool's `changesetArray` model is the right commit shape if we ever batch edits; our current `EditableField` commits per field, which is fine for the record page but will not scale to a grid.
4. **We have no saved views at all** — no `View`, `ViewFilter`, `ViewSort`, `ViewField` tables in `prisma/schema.prisma`. Our contacts list takes only `q` and `page` from the URL. Twenty's `ViewEntity` column list is the target shape, and Attio's "Save for everyone / Save as new view" is the sharing model to copy. **Ship "Current user" as a filter value from day one** — it is the difference between one pipeline view and one per rep.
5. **Our kanban is missing three specific mechanics** (`src/app/(app)/deals/pipeline-board.tsx`): no configurable card content, no collapse, and no sort-conflict handling. Our column header already shows name + count + sum + share bar, which is ahead of several products. The `Stage` model has `probability` but the board does not surface weighted value; Pipedrive's precedence rule (deal-level probability beats stage-level) is the one to implement.
6. **`Deal` has no `stageEnteredAt` and no `lostReason`.** Without the first there is no "days in stage" and no rotting; without the second, `isLost` stages capture nothing. Pipedrive's rotting spec — per-stage day threshold, yellow→red tile, reset on activity/note/email/edit, and the documented gotcha that future-scheduled activity does *not* reset it — is directly implementable against our `Activity` table.
7. **Our `ActivityType` enum is `CALL | EMAIL | MEETING | NOTE | STAGE_CHANGE`**, which conflates a note (content) with a stage change (audit event) and has no task-completion or call-disposition dimension. Attio's timeline mechanic — filter by event type, remembered per object, automation events collapsed by default — is the cheap fix for the noise this will cause.
8. **We have `AuditLog` with `before`/`after` JSON but no UI for it.** Attio's right-click → "View edit history" on a cell is a small surface over data we already write.
9. **Money and derived fields**: we store `Decimal(18,2)` + `currency` per deal, with no FX table. Twenty's `amountMicros` + `currencyCode` and Salesforce's dated exchange rates are the two reference points; at minimum, decide now whether cross-currency pipeline totals are summable (today `getPipelineBoard` sums raw values across currencies, which is wrong the moment a second currency exists).
10. **Our command palette is navigation + search only** (`src/components/command-palette.tsx`: eight static routes plus record search). Linear and Twenty both make the palette contextual and action-capable, and Twenty's palette hosts real inputs. The cheap wins: scope it to the current selection, add `?` for a shortcut overlay, and add `g`-prefixed jumps.
11. **We have no focus/hotkey scoping.** The palette attaches a bare `document.addEventListener("keydown")`. Twenty's `FocusComponentType` stack is the pattern that prevents this breaking the moment we add a modal over a grid.
12. **Empty states are singular where they should be plural.** `src/app/(app)/contacts/page.tsx` distinguishes "Nothing matches that search" from "No contacts yet" — good — but nothing covers read-only, soft-deleted, or filtered-to-zero. Twenty ships five; the empty-CTA that creates an inline row rather than opening a form is also worth copying.
13. **Dark mode**: Attio's June 2026 note ("dark mode is properly dark now… leaner, more predictable palette") and July 2026 note ("popovers, dialogs, and dropdowns now use refined elevated-surface styling in dark mode") independently validate our design system's decision to express dark elevation as lighter surface + stronger border rather than shadow.

## Gaps in a naive build

Assessed against `prisma/schema.prisma`, `src/components/ui/table.tsx`, `src/app/(app)/contacts/page.tsx`, `src/app/(app)/deals/pipeline-board.tsx`, `src/app/(app)/{contacts,deals}/[id]/page.tsx`, `src/components/command-palette.tsx` and `src/app/(app)/layout.tsx` as they stood on 2026-08-24. Ordered by how loudly an experienced CRM user would notice.

**Data model and views**
1. **No saved views.** No `View` / `ViewField` / `ViewFilter` / `ViewSort` tables at all. Every product here treats a view as persisted, named, shareable metadata; our lists take `q` and `page` from the URL and nothing else.
2. **No filter engine.** There is a single text search on contacts. No conditions, no operators, no AND/OR, no groups, no relative dates (`IS_IN_PAST`, `IS_TODAY`, `IS_RELATIVE`), no `is empty` / `is not empty`.
3. **No "current user" as a dynamic filter value** — so a shared "my pipeline" view is impossible without duplicating one per rep.
4. **No user-configurable columns** — no show/hide, no reorder, no resize, no per-view relabel, no per-column formatting (relative dates, decimals, currency display).
5. **No custom fields.** Field sets are fixed columns on `Contact` / `Company` / `Deal`. No field-metadata layer, no field types beyond what Prisma gives us.
6. **No composite field handling.** One `email` and one `phone` per contact — no `additionalEmails`, no `primaryPhoneCountryCode`, no structured address, no `LINKS` with label. Every product studied treats these as composites with a designated primary.
7. **No formula or rollup fields**, so no "open pipeline value" on a company, no computed scores.
8. **No per-relationship attributes.** `Deal.contactId` is a single nullable FK: a deal has one contact, contacts have no role on a deal, and there is no equivalent of Attio's list entry for per-list stage or per-deal role. A record cannot appear twice in a workflow with different context.
9. **No tags or segments** of any kind.

**Table mechanics**
10. **No inline cell editing.** `EditableField` covers record pages only. No soft-focus/edit-mode state machine, no Enter/F2/Escape, no arrow-key cell navigation, no roving tabindex.
11. **No row selection, therefore no bulk actions.** `Tr` accepts a `selected` prop that nothing passes. No checkbox column, no hover-reveal, no shift-click range, no select-all, no bottom action bar, no bulk edit or bulk delete or bulk assign.
12. **No sticky header and no frozen first column**, despite the design system specifying a sticky header. No horizontal scroll shadow.
13. **No sort at all** — no clickable headers, no direction indicator, no multi-level sort, no `aria-live` announcement.
14. **No aggregate footer.** No sum, count, empty/filled tallies. The pipeline page computes one total by hand.
15. **No grouping** with sticky group headers and per-group counts.
16. **No virtualization.** Rows render as plain `<tr>`s inside `overflow-x-auto`, with offset pagination as the only defence. This will fall over well before the scale any of these products target.
17. **No copy/paste to or from a spreadsheet**, and no drag-fill.
18. **No keyboard row navigation** (`j`/`k`, arrows, Enter to open) and no `?` shortcut overlay.
19. **No peek / preview panel.** Clicking a name is a full page navigation with no way back to the row. Every product studied has some form of Space-to-peek or a side panel, and Attio, Twenty and HubSpot make "open in side panel vs full page" a setting.
20. **No column-level filter** from a header menu.

**Record pages**
21. **Fixed `20rem` + `1fr` two-column layout** with hard-coded panels. No configurable sections, no drag-to-resize, no per-user show/hide, no reorder, no "show only filled fields", no compact/standard toggle.
22. **No highlights panel.** Nothing plays the role of Salesforce's compact layout or Attio's six highlight widgets — the most important 4–7 fields are not visually separated from the rest.
23. **No attribute search** on the record page ("open the full attribute list and search by name").
24. **No tabs.** Activity, notes, tasks, emails and files are not separable surfaces, so the page can only grow by getting longer.
25. **No timeline filtering by event type**, and no memory of that choice per object type. With `STAGE_CHANGE` sharing an enum with `NOTE`, the feed will be noise-dominated as soon as automation writes to it.
26. **No comments, no @mentions, no follower/subscription model.** `Activity` has no thread, no parent, no mentions, and there is no `Comment` table. Notifications exist but nothing can mention anyone.
27. **No field-level edit history in the UI** despite `AuditLog` capturing `before`/`after`.
28. **No files or attachments** anywhere in the schema.

**Pipeline**
29. **No `stageEnteredAt`** — no "days in stage", no rotting indicator, no stalled-deal surfacing. This is the single most missed CRM mechanic and it is a one-column migration plus a stage-change hook.
30. **No `lostReason`.** `Stage.isLost` exists but captures nothing, so win/loss analysis is impossible.
31. **No prompt on drop.** Dropping into a stage never asks for anything — no required fields, no lost reason, no won confirmation.
32. **No configurable card content.** Title, company, money and owner avatar are hard-coded.
33. **No column collapse**, no card collapse, no hide-stage.
34. **No multi-card selection or multi-card drag.**
35. **No sort/manual-order conflict handling** — the board has no sort control at all yet, so this is a trap waiting rather than a present bug.
36. **Weighted value is not shown** even though `Stage.probability` exists, and there is no deal-level probability to override it.
37. **Single pipeline board.** `getPipelineBoard` fetches one pipeline; there is no pipeline switcher, no forecast view.
38. **Cross-currency totals are summed as raw numbers**, which silently produces wrong figures the moment a second currency appears.

**Navigation and shell**
39. **Command palette is navigation + record search only** — eight hard-coded routes. No contextual actions, no actions on a selection, no settings jump, no inputs in the palette, no recents.
40. **No hotkey scoping.** A bare global `keydown` listener; nothing resembling Twenty's focus stack. This breaks as soon as a modal or dropdown sits over a grid.
41. **No `g`-prefixed jump navigation and no `?` overlay.**
42. **Sidebar is a static list.** No favourites, no reordering, no customisation, no collapse, no pinning, no saved views listed under each object.
43. **No workspace switcher** (single-org sessions today, but the sidebar has no affordance for it).
44. **Notifications are a page, not a queue.** No snooze, no mark-all-read, no batch operations, no "Upcoming" tab, no per-category delivery preferences.

**CRM behaviour a rep will assume exists**
45. **No duplicate detection or merge UI**, for contacts or companies. `Lead.dedupeKey` protects lead ingestion only; nothing detects that two contacts share an email, and nothing can merge them. Every product except Close has a self-service merge.
46. **No email sync and no thread matching**, therefore no automatic activity. Related and equally absent: participant-based matching, domain-based company matching, auto-creation of contacts from participants (and a setting to turn it off), a system actor to distinguish auto-created records from human-created ones, and a BCC-to-CRM address.
47. **No derived `lastActivityAt` / `lastContactedAt` / `nextActivityAt`** on any record. Nothing can answer "who have I not touched in 30 days" — the single most common CRM query.
48. **No sequences or cadences**, and none of the surrounding machinery: sending windows in the recipient's timezone, blackout dates, wait steps, exit-on-reply goals, run-once semantics, or per-user "send on my behalf" consent.
49. **No task queues or dialling lists.** `Task` exists but there is no "my day" surface, no snooze, no recurrence, no distinction between a generic task and one that completes only when a real call is logged.
50. **No call logging beyond a manual `Activity` of type `CALL`** — no disposition, no duration, no recording, no transcript.
51. **No enrichment**, and no visual convention for enriched-versus-entered data (Attio's lilac cell + sparkle, Folk's sparkle with timestamp).
52. **No record-level or field-level permissions.** `Role` is coarse; there is no object-level tier, no per-list access, no owner-only visibility, no team grouping, and no additive "most permissive wins" resolution. There is also no per-record "visible to" override.
53. **No assignment rules** — no round-robin, no least-loaded, no ordered rule entries.
54. **Soft delete exists (`deletedAt`) but there is no restore UI and no undo anywhere.** No trash, no 30-day window, no toast-with-undo on destructive actions. Note that Attio and Folk also lack general undo, so this is a differentiator rather than a deficiency — but the *restore* path is table stakes.
55. **Import is CSV-only with no dedupe-on-import semantics** documented in the UI: no update-vs-create matching on a unique key, no fill-blanks-only mode, no validation preview flagging bad cells, no failed-row download, no added/updated/merged/skipped summary, no blank-row skipping.
56. **No export** of any kind.
57. **No mandatory fields or validation rules** driven by data rather than code.
58. **No lead-to-contact conversion audit beyond `convertedContactId`** — no record of what was mapped where.
59. **Only two empty states, both on the contacts list.** Nothing for read-only, soft-deleted, filtered-to-zero, or permission-denied. No skeleton loaders anywhere; no delayed-spinner treatment.
60. **No optimistic updates.** Server actions plus `useTransition` mean every edit round-trips before the UI moves. Attio and Linear both treat client-side-first editing as the core investment, and it is the difference reps describe as "fast".
